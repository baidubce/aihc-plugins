# 步 8 交付：控制台启动命令的写法（细则）

> SKILL.md「步 8」只给高亮块与「必须可直接粘贴」的硬要求；怎么把命令写成与自检逐字一致，规则在这里。

## 1. 高亮块之后依次给三样

1. 本次全程的 `假设：` 汇总（没有就不写）；
2. `下一步建议：做完镜像后先用 1 个 benchmark、少量 episode 提一次评测核分数量级，再放全量`；
3. 最后摆 `authorized_keys` 那一问。

上面 1–2 与 `STEP8` 一起写进恢复文件，`STEP8` 与 `step8 written` / `delivered` 的时机见 `恢复点.md`。

## 2. 命令不许留占位符

高亮块里的 `dm05` / `robodojo.yaml` / `/opt/dm05-cache/hf` 只是形状示例。**实际输出必须是可以直接粘贴的
具体命令**：`<name>` 换成②的实际值，yaml 与 envs 的路径取自 `SETUP_INFO` 与实际 `ls`。
**唯一允许留占位符的是平台挂载后的 ckpt 路径**（理由见第 4 条）。

## 3. 命令条数按 benchmark 数给，一条都不许少

- 单 benchmark：给 **1 条**，同样显式带 `--config`（与 L1 跑过的那条逐字一致）。
- 多 benchmark（N 个）：给 **N 条**，一条一行，每条**显式带 `--config /opt/ms-<name>/<benchmark>.yaml`**
  ——目录里有多份 yaml 而命令没传 `--config`，`serve.sh` 会显式报错退出（见 `观测对齐.md` 第 5 节）。
  权重分别指定时 N 条的 `--ckpt` 各不相同，逐条标明哪条对应哪个 benchmark。
- envs 若按 benchmark 不同（如各自的 `HF_HOME`），**随命令逐条给**，不要只给一份让用户自己套。

每条命令**除 `--ckpt` 的值以外，逐字等于**步 7 自检时对应那份 yaml 实际跑过的那条（自检已用
`env -i` + `MS_PORT` 复刻运行时口径），不要在交付时临时改写——多改一个字就等于交付了一条没验证过的命令。

## 4. 为什么 `--ckpt` 可以不同

`--ckpt` 是唯一允许不同的字段：自检用开发机上的真实路径，控制台用平台挂载后的路径，而后者由提交评测时的
`ckptPath` 决定、改造阶段还不存在（见 SKILL.md 阶段 0 输入 ③），本 skill 结构上无法预知，也不要用软链去硬凑成同一字面。

它可以不同的前提是**ckpt 参数无默认值**：填错即启动失败，不会静默跑出一份错分数。
**也因此 `--ckpt` 不能以「有默认值、不填即用 SETUP_INFO 里的路径」交付**——那个默认值指向开发机路径，
平台上根本不存在，真不填就是启动失败；而若脚本里真给了默认值，就退化成「静默加载错权重」。

## 5. 交付之后（不在本 skill 范围）

交接时提示两条已知坑即可：

1. **同一 tag 永不复用**——节点有镜像缓存，同名覆盖不生效（换了镜像而行为没变，通常就是这个）。
2. **镜像地址要节点网络可达、凭据允许拉取**——否则以「镜像拉取失败」出现，离根因很远。

提交后的症状速查表在 `冒烟测试.md`「Troubleshooting」；与上游基线比对要样本量够才定级。
