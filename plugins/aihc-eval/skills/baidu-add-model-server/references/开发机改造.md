# 开发机改造

本文是 SKILL.md 阶段 1、4、5、6 的全文：体检判档 → 上传脚本 → 执行改造 → 离线自检 → 交付前清理。
Ray 解释器那一段单独在 `Ray环境.md`。

所有远端命令按阶段 0 的连接契约执行：`<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE' … REMOTE`。
`CONN_MODE=dry_run` 时只把命令交给用户，一条都不执行。只读的「体检」G2 授权后直接跑；
上传与执行改造由 SKILL.md 的 **G4** 一次批准（计划里已列命令、影响范围、日志路径），执行中不逐段二次确认；
清理的删除由 **G5** 批准。

下文 `<name>` 是模型/框架名（小写下划线）。

## 平台运行时口径（自检要复刻的就是这个）

自定义镜像下，数据面在 MS Pod 里这样起服务：

```text
user  = 镜像 config 里的 User（你的开发机镜像是什么就是什么，多为 root）
cwd   = 容器默认工作目录
cmd   = shlex.split(控制台里填的 command)，每个 token 把 {address}→0.0.0.0:<port>、{port}→<port> 字面替换
        Popen(list) 非 shell：命令里写 $MS_PORT 不会被展开
env   = 镜像 ENV − 代理变量 + CUDA_VISIBLE_DEVICES=<Ray 分配的 1 张卡> + MS_PORT=<port> + 用户 envs
        不注入 HF_HOME / HF_HUB_OFFLINE / HF_MODULES_CACHE，要就自己经 envs 给
port  = coordinator 从 8000 起跨 benchmark 全局递增分配
probe = GET http://127.0.0.1:<port>/config，每 2s 一次，900s 超时；200 后立刻发首帧
network = 无外网、无代理
```

由此推出三条底线：

1. **镜像只带文件，不带 ENV**。你在 shell 里 `export` 的 `PATH`、`UV_CACHE_DIR` 都不会进镜像。
   要钉的东西只能靠文件：uv 缓存用 `/etc/uv/uv.toml` 的 `cache-dir`，可执行入口用软链进镜像 ENV 里**已有**的 `bin` 目录。
2. **改造时是 root，运行时未必**。缓存、解释器、落盘资源都放 `/opt/*` 并 `chmod -R a+rX`，不放 `$HOME`、不依赖 `$HOME`。
3. **运行时无外网**。tokenizer、`trust_remote_code` 代码、JIT/编译产物、`gs://` 资源都要在改造时**真建一次并断言存在**。

推论：开发机上已有的手工调试痕迹（`~/.cache` 里的东西、`/root` 下的实验目录）**不能当作镜像内容的来源**。
脚本里用到什么就由脚本自己产生什么。

## 体检（只读）

```bash
#（体检段**不要** set -eo pipefail：`… | head -1` 的 SIGPIPE 会让整段以 141 中断在第一行）
<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE'
export PYTHONPATH="${PYTHONPATH:-}"
echo "== OS / GPU"
. /etc/os-release && echo "$PRETTY_NAME"; ldd --version 2>/dev/null | head -1
nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader 2>/dev/null || echo "no nvidia-smi"
echo "== 当前用户（改造时）"
id; echo "HOME=$HOME"
echo "== 镜像 ENV 与入口（PID1；镜像只带文件不带 ENV，所以这里的 PATH 才是运行时口径）"
tr '\0' '\n' < /proc/1/environ | grep -E '^(PATH|HOME|LD_LIBRARY_PATH|CONDA|UV_)' ; tr '\0' ' ' < /proc/1/cmdline; echo
echo "== Ray 解释器（KubeRay 用 PATH 上第一个 ray）"
type -a ray 2>/dev/null || echo "PATH 上无 ray"      # bash 的 command -v 不认 -a
type -a uv  2>/dev/null || echo "PATH 上无 uv"
for py in /opt/conda/bin/python /usr/bin/python3 /usr/local/bin/python3; do
  [ -x "$py" ] || continue
  "$py" -c 'import sys,platform;print(sys.executable,platform.python_version())'
  "$py" -c 'import ray;print("  ray",ray.__version__)' 2>/dev/null
done
echo "== 模型环境（手工跑通时用的那个）"
ls -d /opt/conda/envs/* /root/miniconda3/envs/* /opt/*-env 2>/dev/null
echo "== 关键路径在根盘还是挂载盘（SOURCE 非 overlay 即不进镜像）"
for p in / /root /opt /etc /tmp /workspace /mnt; do
  [ -e "$p" ] && findmnt -no TARGET,SOURCE,FSTYPE -T "$p" | sed "s#^#$p -> #"
done
echo "== 空间与可写层体积"
df -h / | tail -1
du -sh /root /opt /workspace 2>/dev/null || true
echo "== 外网连通（只探测，不配代理；运行时无外网，改造时才有）"
curl -s -o /dev/null -w 'pypi(直连):%{http_code}\n' --max-time 10 --noproxy '*' https://pypi.org/simple/ || echo "pypi(直连):fail"
if env | grep -qi -E '^(http|https)_proxy='; then
  curl -s -o /dev/null -w 'pypi(经环境既有代理):%{http_code}\n' --max-time 10 https://pypi.org/simple/ || echo "pypi(经环境既有代理):fail"
fi
echo "== 代理与凭据落点（只列路径，不打印内容）"
env | grep -i -E '^(http|https|no|all)_proxy=' | sed 's/=.*/=<set>/' || true
for f in /etc/environment /etc/pip.conf /etc/uv/uv.toml /root/.bashrc /root/.profile /root/.config/pip/pip.conf \
         /root/.gitconfig /root/.git-credentials /root/.netrc /root/.docker/config.json \
         /root/.cache/huggingface/token /root/.huggingface/token /root/.bash_history /etc/apt/apt.conf.d/*proxy*; do
  [ -f "$f" ] && { grep -l -i -E 'proxy|token|password|passwd|secret|[-_](ak|sk)=|\b(access_?key|secret_?key)\b' "$f" >/dev/null 2>&1 && echo "疑似敏感: $f" || echo "存在: $f"; }
done
ls -la /root/.ssh 2>/dev/null | awk 'NR>1{print "ssh: "$NF}' || true
REMOTE
```

⚠️ 把 `/proc/1/environ` 的输出贴给用户前**过滤掉凭据类键**（`*TOKEN*`、`*SECRET*`、`*PASSWORD*`、`*_AK`、`*_SK`），
上面的 `grep -E` 已经只取需要的键，不要改成全量 dump。

⚠️ 敏感文件那条 `grep` **不要把 `ak`/`sk` 写成裸词**：`ak` 会命中 task / peak / break，`sk` 会命中 disk / mask / risk，
几乎每个文件都被标成「疑似敏感」，等于这条检查没有信息量。要带分隔符或词边界（上面的写法即此意）。

判档（见 SKILL.md 阶段 1）。重点看四处：

- `type -a ray` 的**第一个**是否 Python 3.13.12 + ray 2.49.2 —— 不是（尤其**整机没有 `/opt/conda`**）即重档，走 `Ray环境.md`；
- 镜像 ENV 的 `PATH` 里有没有**根盘上**的 `bin` 目录可供软链（通常 `/usr/local/bin`）；
- `/opt`、`/etc`、`/root` 与模型目录的 SOURCE 是 overlay（进镜像）还是 PFS/NFS（**不进镜像**）；
- 模型当前依赖的远端资源清单（对照作者 README / 你手工跑通时的下载日志），逐个列进 `setup.sh`。

ckpt 通常留在挂载数据源（如 `/mnt/pfs/...`）上**不进镜像**，运行时由平台挂载、经启动命令参数传入。
要烘进镜像的只有「运行时无法重新获取」的小件：tokenizer、remote code、编译产物。

## 上传

`SSH_CMD` 形态各异，统一用 `cat >` 走 stdin，不转换成 scp。本地工作目录**不入库**。
两个自检脚本从本 skill 的 `scripts/` 直接拷进工作目录一起上传。配置按 benchmark 成组：`_base.yaml` 一份，
`<benchmark>.yaml` 与 `obs.<benchmark>.json` 每个 benchmark 各一份（形状见 `脚本模板.md`「多 benchmark 配置」）：

```bash
D=~/.cache/baidu-add-model-server/<host>_<port>   # 本地不入库工作副本（= SKILL.md 的 $W）
cp <skill目录>/scripts/ray_env_check.sh <skill目录>/scripts/ms_selfcheck.py "$D/"
<SSH_CMD> -o BatchMode=yes 'mkdir -p /tmp/setup-<name>'
# 只传显式列出的文件：form.yaml / PROGRESS 是本地恢复文件，不上传
FILES=(setup.sh server.py serve.sh ray_env_check.sh ms_selfcheck.py _base.yaml)
for b in <benchmark> ...; do FILES+=("$b.yaml" "obs.$b.json"); done   # 与 BENCHMARKS 一致
for f in "${FILES[@]}"; do
  [ -f "$D/$f" ] || { echo "缺 $f" >&2; exit 1; }
  <SSH_CMD> -o BatchMode=yes "cat > /tmp/setup-<name>/$f" < "$D/$f"
done
(cd "$D" && shasum -a 256 "${FILES[@]}")
<SSH_CMD> -o BatchMode=yes 'sha256sum /tmp/setup-<name>/*'     # 两端逐个比对
```

两端 sha256 不一致就别执行——多半是 heredoc/编码问题，重传。

## setup.sh 模板

**开发机上对镜像的一切改动只来自这一份脚本**，不在交互 shell 里手敲 `pip install` / `cp`。
任何一步失败就改本地脚本 → 重新上传 → **整份重跑**，不在远端手工补。
`Ray环境.md` 的内容是本脚本的第 1 段（重档必须有；轻档可省，但要保留断言）。

```bash
#!/usr/bin/env bash
# ms-<name> 开发机改造脚本。镜像相对开发机原镜像的全部改动只来自本脚本。
# 用法（root）：[SETUP_PROXY=http://host:port] bash setup.sh
# 同一份脚本可在新开发机上原样重跑，用于重建产物。
set -euo pipefail

NAME=<name>
SRC_DIR="$(cd "$(dirname "$0")" && pwd)"
MS_DIR=/opt/ms-${NAME}                        # 服务代码与启动器
ASSET_DIR=/opt/${NAME}-cache                  # 运行时资源落盘处，不放 $HOME
MODEL_ENV=/root/miniconda3/envs/<env>         # 已跑通的模型环境（或新建 /opt/<name>-env，此时 SETUP_INFO 写 env_created_by_setup=1）
HARNESS_DIFF='<none|未装|与 v0.5.0 的差异摘要>'     # 5d 核对得出（键名/维度/protocol_version/HELLO/chunk 语义），写死在脚本里，随 setup_sha256 变
LINK_DIR=/usr/local/bin

[ "$(id -u)" = 0 ] || { echo "需要 root" >&2; exit 1; }
mkdir -p "$MS_DIR" "$ASSET_DIR"

# ── 0. 镜像 ENV 回取：SSH 会话不继承它，改造要与运行时同口径
IMG_PATH="$(tr '\0' '\n' < /proc/1/environ | sed -n 's/^PATH=//p' | head -1)"
[ -n "$IMG_PATH" ] || { echo "取不到镜像 PATH" >&2; exit 1; }

# ── 1. Ray 解释器（重档：整段照抄 Ray环境.md；轻档：只留下面的断言）
#    …（见 references/Ray环境.md）…
#    断言统一走脚本，两处同一份口径（改造后 / 交付前清理后各跑一次）
bash "$SRC_DIR/ray_env_check.sh"

# ── 2. 网络：只探测并提示，不默认配代理，也不在这里硬失败
#     「要不要外网」是探测的结论，不是前提：第 4、5 段可能整段跳过（依赖已装好、资源已落盘），
#     那就一次都不用联网。所以这里只把连通性结论打出来，硬失败交给真正要下载的那一步（need_net）。
#     **不要默认 export 任何 http_proxy**：代理地址随环境变化（换一台开发机/换一个网络环境就不存在），
#     默认写上去会在没有该代理的环境里把每个下载都挂成连接超时，症状指向「网络慢」而不是「代理不存在」。
#     只有用户显式传入 SETUP_PROXY 时才生效，且只在本进程内，不写任何配置文件、不进镜像。
NET_TARGETS=(https://pypi.org/simple/)        # 按本模型实际依赖改（如 https://huggingface.co）
if [ -n "${SETUP_PROXY:-}" ]; then
  export http_proxy="$SETUP_PROXY" https_proxy="$SETUP_PROXY" \
         HTTP_PROXY="$SETUP_PROXY" HTTPS_PROXY="$SETUP_PROXY" \
         no_proxy=127.0.0.1,localhost NO_PROXY=127.0.0.1,localhost
  echo "net: 经显式传入的 SETUP_PROXY"
else
  echo "net: 直连（未传 SETUP_PROXY，也不读环境里既有的代理变量以外的任何配置）"
fi
NET_OK=0
for u in "${NET_TARGETS[@]}"; do
  if curl -s -o /dev/null --max-time 10 "$u"; then echo "net ok: $u"; NET_OK=1; else echo "net 不可达: $u"; fi
done
[ "$NET_OK" = 1 ] || echo "net: 外网不可达——只要后面各步都能复用已有产物就仍可跑通，真要下载时会在该步失败"

# 真要下载前调它，而不是在脚本开头无条件判死（与 Ray环境.md 同一个函数）
need_net() {                                  # $1=用途描述
  [ "$NET_OK" = 1 ] && return 0
  echo "需要外网才能$1，但 ${NET_TARGETS[*]} 均不可达。" >&2
  echo "  直连不通时显式传入本机实际可用的代理：SETUP_PROXY=http://<host>:<port> bash setup.sh" >&2
  exit 1
}

# ── 3. 落服务代码与启动器（自检脚本一并落进 /opt：交付前复跑与线上排障都要用）
install -m 0644 "$SRC_DIR/server.py" "$MS_DIR/server.py"
install -m 0755 "$SRC_DIR/serve.sh"  "$MS_DIR/serve.sh"
install -m 0755 "$SRC_DIR/ray_env_check.sh" "$MS_DIR/ray_env_check.sh"
install -m 0644 "$SRC_DIR/ms_selfcheck.py"  "$MS_DIR/ms_selfcheck.py"

#    配置按 benchmark 成组落：_base.yaml + 每个 benchmark 一份 <b>.yaml 与同名 obs.<b>.json。
#    BENCHMARKS 与接入表单 ④ 逐项一致；yaml/obs 缺一即失败（缺 obs 会让 L1 的 obs_spec 用例 FAIL，
#    缺 yaml 则 serve.sh 起不来），yaml 里出现 checkpoint 直接失败（权重只经 --ckpt 传入）
BENCHMARKS=(<benchmark> ...)                  # 如 (robodojo) 或 (robodojo robotwin)
install -m 0644 "$SRC_DIR/_base.yaml" "$MS_DIR/_base.yaml"
for b in "${BENCHMARKS[@]}"; do
  case "$b" in _*) echo "benchmark 名不许以 _ 开头：$b" >&2; exit 1 ;; esac
  for f in "$b.yaml" "obs.$b.json"; do
    [ -f "$SRC_DIR/$f" ] || { echo "缺 $f" >&2; exit 1; }
    install -m 0644 "$SRC_DIR/$f" "$MS_DIR/$f"
  done
done
if grep -n '^[[:space:]]*checkpoint[[:space:]]*:' "$MS_DIR"/*.yaml; then
  echo "yaml 里不许写 checkpoint：权重只经 --ckpt 传入" >&2; exit 1
fi

#    解释器路径只有一个来源：上面的 MODEL_ENV。serve.sh 里写的是 @MODEL_ENV@ 占位符，这里替换成实际值，
#    并断言替换真的发生了（漏替换会在平台上以「解释器不存在」失败，而开发机自检却是好的）
sed -i "s|@MODEL_ENV@|$MODEL_ENV|g" "$MS_DIR/serve.sh"
if grep -q '@MODEL_ENV@' "$MS_DIR/serve.sh"; then echo "serve.sh 仍有未替换的 @MODEL_ENV@" >&2; exit 1; fi
grep -q "^MODEL_ENV=\"$MODEL_ENV\"" "$MS_DIR/serve.sh" || { echo "serve.sh 未写入 MODEL_ENV" >&2; exit 1; }
[ -x "$MODEL_ENV/bin/python" ] || { echo "MODEL_ENV 解释器不存在：$MODEL_ENV/bin/python" >&2; exit 1; }

# ── 4. 模型环境补依赖（协议栈：websockets + msgpack + 一个 HTTP 框架）
#     装进模型环境，不碰 Ray 那个环境。pillow 是 ms_selfcheck.py 跑 png/jpeg 用例要的（多数推理栈已自带）
#     先探测：已装齐就跳过，不用联网（重复改造、或推理栈本来就带这几个包时常见）
if "$MODEL_ENV/bin/python" -c "import websockets, msgpack, PIL" 2>/dev/null; then
  echo "DEPS_REUSE: 模型环境已有 websockets + msgpack + pillow，跳过安装"
else
  need_net "安装协议栈依赖 websockets/msgpack/pillow"
  "$MODEL_ENV/bin/python" -m pip install --no-input "websockets>=12" msgpack pillow
fi
"$MODEL_ENV/bin/python" -c "import websockets, msgpack; print('proto deps ok')"

# ── 5. 运行时资源真建一次并断言（--help 不构造模型，不算断言）
#     运行时无外网：tokenizer / trust_remote_code 代码 / JIT 编译产物 / gs:// 资源都要在这里真建一次，
#     路径用 env 钉到 $ASSET_DIR（不能落 $HOME：运行时 HOME 可能不同、也可能不可写）。
#     下面是 HF 栈的实例，换模型时照同一形状改：先真构造，再 test 断言产物存在。
export HF_HOME="$ASSET_DIR/hf"
export HF_MODULES_CACHE="$ASSET_DIR/hf-modules"      # trust_remote_code 会往这里写，必须可写
mkdir -p "$HF_HOME" "$HF_MODULES_CACHE"
#     资源来源指纹：只看 tokenizer*.json 在不在认不出「同名换了模型」，必须比对来源。
#     本地路径（含 ckpt 内 tokenizer）用文件内容 sha256，原地覆盖权重也认得出；HF repo 用 repo@revision
ASSET_SRC="<hf-repo>@<revision>"   # 或："$(cat <ckpt>/tokenizer*.json | sha256sum | cut -d' ' -f1)"
FP_FILE="$ASSET_DIR/.asset_fingerprint"
if [ "$(cat "$FP_FILE" 2>/dev/null)" != "$ASSET_SRC" ] && [ -e "$FP_FILE" ]; then
  echo "ASSET_REBUILD: 指纹变化 $(cat "$FP_FILE") -> $ASSET_SRC"
  rm -rf "$HF_HOME" "$HF_MODULES_CACHE"; mkdir -p "$HF_HOME" "$HF_MODULES_CACHE"
fi
if [ "$(cat "$FP_FILE" 2>/dev/null)" = "$ASSET_SRC" ] \
   && [ -n "$(find "$HF_HOME" -name 'tokenizer*.json' -print -quit)" ]; then
  echo "ASSET_REUSE: $HF_HOME 指纹一致且已有 tokenizer 产物，跳过下载"
else
  need_net "下载 tokenizer / remote code 到 $HF_HOME"
  "$MODEL_ENV/bin/python" - <<'PY'
import transformers
# 真构造一次：下载 config/tokenizer/remote code 并落进 HF_HOME。不要用 --help 或 list_models 糊弄。
transformers.AutoTokenizer.from_pretrained("<hf-repo-or-local-path>", trust_remote_code=True)
print("tokenizer built")
PY
fi
#     断言与「这次有没有下载」无关：复用路径也必须过（否则等于没验）
test -n "$(find "$HF_HOME" -name 'tokenizer*.json' -print -quit)" \
  || { echo "tokenizer 未落盘到 $HF_HOME" >&2; exit 1; }
echo "$ASSET_SRC" > "$FP_FILE"                       # 同值写进 SETUP_INFO 的 asset_fingerprint=

# ── 6. 断网复验：与运行时同口径（代理指死端口，漏网的外网访问立刻失败而不是挂超时）
( export http_proxy=http://127.0.0.1:9 https_proxy=http://127.0.0.1:9 \
         HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9 \
         no_proxy=127.0.0.1,localhost NO_PROXY=127.0.0.1,localhost
  "$MODEL_ENV/bin/python" "$MS_DIR/server.py" --help >/dev/null )

# ── 7. 运行时用户未必是 root
chmod -R a+rX "$MS_DIR" "$ASSET_DIR"

# ── 8. 出处：进镜像，复现时唯一凭据
{
  echo "name=$NAME"
  echo "setup_sha256=$(sha256sum "$SRC_DIR/setup.sh" | cut -d' ' -f1)"
  echo "server_sha256=$(sha256sum "$MS_DIR/server.py" | cut -d' ' -f1)"
  echo "model_env=$MODEL_ENV"
  echo "benchmarks=${BENCHMARKS[*]}"
  echo "asset_dir=$ASSET_DIR"
  echo "asset_fingerprint=$(cat "$ASSET_DIR/.asset_fingerprint" 2>/dev/null || echo none)"
  echo "ray=$(env -i PATH="$IMG_PATH" HOME=/root ray --version 2>&1)"
  echo "harness_installed=$("$MODEL_ENV/bin/python" -c 'import vla_eval._version as v; print(v.version)' 2>/dev/null || echo 未装)"
  echo "harness_diff=$HARNESS_DIFF"
  echo "date=$(TZ=Asia/Shanghai date +%F)"
} > "$MS_DIR/SETUP_INFO"
cp "$SRC_DIR/setup.sh" "$MS_DIR/setup.sh"
echo "SETUP_OK"
```

要点：

- `MODEL_ENV` 在 `$HOME` 下（conda 常见）也没关系——`$HOME` 在根盘上就会进镜像；
  但**不要依赖 `$HOME` 变量**，脚本与启动器里一律写绝对路径（运行时 HOME 可能不同）。
- conda 环境里的可执行文件 shebang 写死了绝对路径，所以启动器直接调 `$MODEL_ENV/bin/python`，
  不 `conda activate`、不依赖 PATH。
- ckpt **不进镜像**，不在脚本里拷；也**不要给 ckpt 参数默认值**（见 SKILL.md「三个没有报错但分数是错的」）。
- 第 5 步的 `--help` 只验证了解释器能 import，不等于能加载模型；真正的验证在「自检」。
- 第 5 步在镜像里**只是把资源落盘**，raw 启动路径**不会自动注入** `HF_HOME` / `HF_MODULES_CACHE`：
  控制台 envs 里要按 `$ASSET_DIR` 的实际路径再给一遍（`HF_HUB_OFFLINE=1` 一并给），
  且 `HF_MODULES_CACHE` 必须指向**可写**目录——指到只读挂载时 transformers 拷 remote code 会 `EROFS`。
- 模型确实不依赖任何远端资源时，第 5 步可以删掉，但要在 `SETUP_INFO` 里写明「无运行时下载」，
  别留一段注释占位——下次复现的人无法判断是「不需要」还是「忘了做」。

## 执行改造

G4 的计划里要写明（用户选「看 setup.sh」时给全文）：会联网下载的依赖与资源、会写的路径
（`/opt/ms-<name>`、`/opt/<name>-cache`、`/etc/uv/uv.toml`、`/opt/uv-*`、`/opt/ray-py`、`$LINK_DIR/{ray,uv}`）、日志位置。

```bash
<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE'
set -eo pipefail
L=/tmp/setup-<name>.log
CMD='bash /tmp/setup-<name>/setup.sh > /tmp/setup-<name>.log 2>&1; echo "EXIT=$?" >> /tmp/setup-<name>.log'
if command -v tmux >/dev/null; then
  tmux new-session -d -s setup-<name> "$CMD"
else
  setsid nohup bash -c "$CMD" >/dev/null 2>&1 & echo $! > /tmp/setup-<name>.pid   # 无 tmux 时判活；setsid 使 pid=进程组号，kill 用 kill -- -<pid>
fi
echo "started, log: $L"
REMOTE

# 轮询（只读）
<SSH_CMD> -o BatchMode=yes 'tail -n 20 /tmp/setup-<name>.log'
```

轮询约每 30s 一次，见到 `EXIT=` 即止；每段结论（`RAY_REUSE:` / `SETUP_OK` 等）出现时报一行进度，不贴日志。
发起上面的启动**之前**在 `PROGRESS` 追加 `setup\tstarted\t<name>\t<时间>`；`EXIT=0`、`SETUP_OK` 与 `ls` 复核都过后才追加 `setup\texit=0`。日志 mtime 早于本次 `started` 的 `EXIT=` 不采信（旧日志未清）。超时上限：计划里有任一项下载就按约 60 分钟，全 REUSE 约 10 分钟。超时不 kill、不重跑（tmux 里可能还在装），按「出错」格式停，
`需要你：` 再等 30 分钟（推荐，追加 `setup\textend`，预算从它重算）/ 看 tmux（自己去看会话）/ 取消。选后两项都是终态：不 kill、保留现场（kill 只在回退时经确认才做，见 `改主意回退.md`），
`PROGRESS` 追加 `stop\t7\t看 tmux`/`stop\t7\t取消`，给 `下一步建议：`（如「恢复会话后会先查 `EXIT=` 再接着轮询」）。
auto 模式下最多自动续等 1 次（同样追加 `setup\textend`，标进 `假设：`），再超时必停问，不无限续等。

**默认不配代理**：直接跑。`setup.sh` 第 2 段只探测并打一行 `net:` 结论，**不在那里判死**——
各步会先探测能不能复用已有产物（打 `RAY_REUSE:` / `PY_REUSE:` / `DEPS_REUSE:` / `ASSET_REUSE:`），
全都命中时整份脚本一次都不联网。体检里 `pypi(直连)` 已经是 200 时不要加代理。
只有脚本在某一步打出「需要外网才能…」时，才把**这台机器上实际可用**的代理前置到 `CMD` 里：
`SETUP_PROXY=http://<host>:<port> bash /tmp/setup-<name>/setup.sh …`。它只在脚本进程内生效，
不写进任何配置文件、不进镜像。**不要把某台机器的代理地址固化进脚本或文档**——换环境后该地址往往不存在，
所有下载会挂成连接超时，症状像「网络慢」而不是「代理不存在」。

## 自检（交付门禁，同口径）

以**镜像的 User**、`env -i` 只带镜像 ENV + 数据面注入项启动 MS。代理指向死端口，
任何漏网的外网访问立刻失败而不是挂到超时。**多选了 N 个 benchmark 就把下面两段按 `B` 各跑一遍**，
每遍之间先停掉上一个 MS（见本节末尾）；`B` 与 `--config` / `--obs-spec` 必须同名配对。

```bash
<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE'
set -eo pipefail
NAME=<name>
B=<benchmark>                                 # 本遍验哪个 benchmark
PORT=18000
CKPT=<开发机上的 ckpt 路径>                   # per_benchmark 时取本 benchmark 那条；步 8 控制台改填平台挂载后的路径，仅此字段可不同

IMG_ENV=()
while IFS= read -r -d '' kv; do
  case "${kv%%=*}" in *proxy*|*PROXY*) ;; *) IMG_ENV+=("$kv") ;; esac
done < /proc/1/environ
DEAD=http://127.0.0.1:9
RUN_ENV=("${IMG_ENV[@]}" CUDA_VISIBLE_DEVICES=0 MS_PORT=$PORT
  http_proxy=$DEAD https_proxy=$DEAD HTTP_PROXY=$DEAD HTTPS_PROXY=$DEAD
  no_proxy=127.0.0.1,localhost NO_PROXY=127.0.0.1,localhost)
# 用 HF 栈的话按控制台 envs 的计划补：HF_HOME=<只读目录> HF_HUB_OFFLINE=1 HF_MODULES_CACHE=/tmp/hf_modules

echo "== 启动 MS（命令与控制台里要填的那条逐字一致；端口由 RUN_ENV 里的 MS_PORT 注入，命令里不出现）"
rm -f /tmp/ms-selfcheck.log
{ [ -f /tmp/ms-selfcheck.pid ] && kill "$(cat /tmp/ms-selfcheck.pid)"; } 2>/dev/null || true; rm -f /tmp/ms-selfcheck.pid
pkill -f "[/]opt/ms-$NAME/" || true
for _ in $(seq 30); do curl -s -o /dev/null "http://127.0.0.1:$PORT/config" || break; sleep 1; done
curl -s -o /dev/null "http://127.0.0.1:$PORT/config" && { echo "$PORT 仍被旧 MS 占用"; exit 1; }   # 不让旧 MS 冒充新代码；这一失败不计入 selfrepair
( exec env -i "${RUN_ENV[@]}" bash /opt/ms-$NAME/serve.sh --config /opt/ms-$NAME/$B.yaml --ckpt "$CKPT" ) \
  > /tmp/ms-selfcheck.log 2>&1 &
echo $! > /tmp/ms-selfcheck.pid

T0=$(date +%s)
until curl -sf "http://127.0.0.1:$PORT/config" >/dev/null; do
  kill -0 "$(cat /tmp/ms-selfcheck.pid)" 2>/dev/null || { echo "MS 提前退出"; tail -50 /tmp/ms-selfcheck.log; exit 1; }
  [ $(( $(date +%s) - T0 )) -lt 900 ] || { echo "/config 900s 未就绪"; kill "$(cat /tmp/ms-selfcheck.pid)"; exit 1; }
  sleep 2
done
echo "/config 200，用时 $(( $(date +%s) - T0 ))s"
curl -s "http://127.0.0.1:$PORT/config"; echo
grep -n -i 'ckpt\|model_path\|checkpoint\|loading\|\[ms\] config' /tmp/ms-selfcheck.log | head -6
REMOTE
```

`/config` 返 200 只是起点——它只证明端口通了，不证明能推理，必须发**真实形状**的观测计时。
这步交给本 skill 的 `scripts/ms_selfcheck.py`（零 harness 依赖，只要 `websockets` + `msgpack` + `numpy`，
png/jpeg 另需 `pillow`），它把 `协议自检.md` 里可机械判定的条目全跑一遍，逐条 PASS/FAIL：

观测口径文件 `obs.<benchmark>.json` 在本地 `$D/` 写好、随「上传」走、由 `setup.sh` 第 3 段落到 `/opt/ms-<name>/`，
**不在远端临时生成**（L1 与运行时 yaml 里的 `obs_spec` 必须是同一份）。下例是 `$D/obs.robodojo.json`：

```json
{
  "images": {
    "cam_head": [480, 640, 3],
    "cam_left_wrist": [480, 640, 3],
    "cam_right_wrist": [480, 640, 3]
  },
  "states": 14,
  "state_key": "state",
  "task_description": "pick up the cup and place it on the tray"
}
```

- 相机键名必须逐字等于该 benchmark 实发的键名（不是模型内部的 image_prompt 名），否则自检按假键名自洽通过、上平台每帧 ERROR。
- `states` 是维度声明（0 表示该 benchmark 不发 state），线缆字段名由 `state_key` 给（RoboDojo 单数 `state`，§4）。
- H/W 是 **RoboDojo 的实值**，已核实：RoboDojo `env_cfg/camera/template.py:2,9,16,23` 硬编码 (640,480) 且无覆盖入口，
  harness 全链路不 resize（`评测集观测口径.md` §3.7）。别拿参考 MS warmup 里的 224×224 当实发尺寸——那是 openpi 内部
  resize 后的模型输入尺寸；写错了 L1 照样全通过（obs_spec 只校验格式不校验真值），上平台才暴露。
- 换 benchmark / 上游换 pin 必须**逐个重查**（查法见 §3.9），不许从另一个 benchmark 的 obs 复制。

```bash
<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE'
set -eo pipefail
NAME=<name>
B=<benchmark>                                 # 与上一段启动 MS 时的 B 相同
OBS=/opt/ms-$NAME/obs.$B.json
[ -f "$OBS" ] || { echo "缺 $OBS：setup.sh 未落该 benchmark 的观测口径" >&2; exit 1; }

# 解释器：模型环境那个最省事（装协议栈时已经把 websockets/msgpack 装进去了）
MODEL_PY=/root/miniconda3/envs/<env>/bin/python
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  "$MODEL_PY" /opt/ms-$NAME/ms_selfcheck.py \
    --url ws://127.0.0.1:18000 \
    --obs-spec "$OBS" \
    --steps 3 --first-frame-budget 30
REMOTE
```

通过标准（交付门禁绝对口径）：**通过数 == 用例总数、退出码 0、且全程未带 `--skip`**——`--skip` 会同时缩小
分子分母，跳掉用例后仍打印「n/n 通过」，所以按用例总数核、不按打印的 n/n 核。失败项直接给出用例名
（如 `inference.ep0.step0.one_dim`），对照 `协议自检.md` 同名条目修。`--list` 列出用例名；`--skip` 仅供
改造中途快速试跑，交付门禁不带。唯一的合法跳过是缺 `pillow` 时 png/jpeg 两条**由脚本自动降 INFO**。
`session_isolation` / `seq_echo` / 畸形帧容错都是真机缺陷用例、不是「不适用」项，任何情况下不许 `--skip` 跳过。

脚本看不到服务端日志，所以这两条仍要人工核对（启动段里那条 `grep ckpt` 的输出）：

- 日志里打印的 ckpt 路径就是传入的那个；
- 观测口径与上游逐项对齐（相机键名、RGB/BGR、HWC/CHW、归一化、state 维度），逐条清单见
  `协议自检.md`「观测对齐」，为什么不能改模型侧参数去迁就观测见 `SKILL.md`「阶段 3.5」。
  **`obs_spec` 用例只验格式不验真假**：键名是不是真的那套，只能人工对出处。

模型环境里装了 harness 时，可另外跑一次 `vla-eval test -c <server-config>.yaml` 作交叉验证，但**不替代**上面这步
——`ms_selfcheck.py` 才是与平台数据面同口径（手写同样的 msgpack 信封，不经 harness 的封装）。

然后停掉 MS：

```bash
<SSH_CMD> -o BatchMode=yes 'kill "$(cat /tmp/ms-selfcheck.pid)" 2>/dev/null; pkill -f "[/]opt/ms-<name>/" || true'   # [/] 防止匹配到执行它的远端 shell 自己
```

能用 `unshare -n` 的开发机（需 CAP_SYS_ADMIN，多数没有）可把 MS 与客户端放进同一个无网络 namespace，
比死代理更严格；没有该能力时，死代理（`http://127.0.0.1:9` + `no_proxy=127.0.0.1,localhost`）就是最终口径。

逐条过 `协议自检.md` 后再进入清理。

## 清理（交付前）

将来「保存为镜像」会把整个可写层带走。清理是交付前的硬步骤：**私钥、凭据（token/AK/SK）、shell/python
history、代理行必删，清理后复跑整套 L1 也必做；用户催「别删了直接交付」「清理我自己来」「L1 刚才过了不用再跑」都不构成跳过**
——可由用户定去留的只有「与凭据无关」的大目录（实验 ckpt、旧 venv）和 `authorized_keys`（时机以 SKILL.md 阶段 6 为准：步 8 高亮块之后单独问，见下）。先**只列不删**，把清单给用户确认（**不打印文件内容**）：

```bash
<SSH_CMD> -o BatchMode=yes 'bash -s' <<'REMOTE'
set -eo pipefail
echo "== 改造/自检残留"

         /root/.git-credentials /root/.netrc /root/.docker/config.json \

done
grep -l -i -E '^\s*(export\s+)?(http|https|all)_proxy=' /root/.bashrc /root/.profile /etc/environment /etc/profile.d/* 2>/dev/null \

echo "== MS 落点与废产物（G5 复核：form.yaml 之外的 yaml/obs、rename→ 链里旧名的 /opt/ms-* 与 -cache 应已不在；链外的只读汇报）"

REMOTE
```

清单经 SKILL.md 的 **G5** 一次确认后再删（可选大目录**不单独成问**：在 G5 清单里列出路径与大小，默认保留并写进 `假设：`，
只在「先看清单逐项」的单项问里可删——不要让裸「1」删掉用户的实验 ckpt）。原则：

- 删：`/tmp` 残留、shell/python history、HF token、git/docker/netrc 凭据、
  `~/.bashrc` 等里的代理行（用 `sed -i '/_proxy=/d'` **定点删，不删整个文件**）、`$HOME/.local/bin` 下的安装器残留。
- `/root/.ssh/authorized_keys` 是本会话的登录凭证：**不进 G5 的「全删」**，
  去留的时机与选项以 SKILL.md 阶段 6 为准（步 8 高亮块之后单独问），不在这里另立一套。**私钥一律删，不读不打印**。
- 不删：`/opt/ms-<name>`、`/opt/<name>-cache`、`/opt/ray-py`、`/opt/uv-*`、`/etc/uv/uv.toml`、模型环境。
  **例外**：回退产生的废产物（改名前的 `/opt/ms-<旧name>/` 与 `/opt/<旧name>-cache`、换掉的 obs/yaml）——
  这条「不删」防的是误删当前服务，不含废产物；它们由**差量 G4** 批准、在重跑 `setup.sh` 前删，G5 只复核已不在。
- **不 `uv cache prune`**（会删预建环境）；与本 MS 无关的大目录（实验 ckpt、旧 venv、源码树）列出体积供用户定去留，不替用户建议删。
  复跑通过后再 `rm -rf /tmp/ms-selfcheck.*`（复跑自己产生的残留），不另问。
