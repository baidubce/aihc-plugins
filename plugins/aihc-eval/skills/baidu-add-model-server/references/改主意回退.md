# 改主意回退矩阵

## G4 之前（开发机零写入）

- 改表单一行：回显**改动行 + 它的派生行**（如换 benchmark 带出的 `images`/`state_key`/`state_dim`/`dtype_range`/`sub_bench`/`bench_params`/`camera_slot_map` value，
  以及随 benchmark 变的 ⑥B/L3 行 `state_layout`/`action_semantics`/`action_denormalize_by`（含 `unnorm_key`）——这些**重问**（`observation_params`/`image_flip` 只重查），不沿用旧值；
  换回本会话已确认过的 benchmark 时，可把 `history:` 里同 benchmark 最近一组 `g3 已确认` 的 L3 值作为一个选项摆出，不标推荐、不当成已确认），
  只确认这些行，不重发整张表；重问前先把 ⑥B/L3 行置 `未提供`（`[查表]` 派生行只重查，新值写 `重核`）、旧值移进 `history:`、`g3_confirmed: false`，不要带着旧值中断；改完重跑 5d。只在 ③ ckpt 行本身变了且行尾仍有 `(probe)` 时重问 G3 第 2 问；用户给了新值就去掉 `(probe)`、改标 `[L1]`。
- 换机：按下表 ① 行走，`[探测]`/`[查表]` 行全部重新 probe/查表，G3 第 1 问整表重摆。
- 换模型：②③⑤⑥A/⑥B/L3 全部清空重收（模型口径换了，旧值即使用户亲口给过也不沿用），`prefill_accepted` 与 `history:` 清空、删 `$W/predict_snippet.py`、`g3_confirmed: false`，只保留 ①④。
- `per_benchmark` 下换掉某个 benchmark：该项的 `ckpt` 置 `未提供` 重问，不沿用旧 benchmark 的权重路径。
- 已选终态的反悔：`dry_run` → 要执行：开发机已有对得上的 `SETUP_INFO`（用户自跑过）就按 `恢复点.md` 分支表「曾有 `G2\tdry_run`」行走，不另走一套；否则重摆 G2，从步 3 重探，只回显与用户贴回值不同的 `[探测]` 行重确认，无差异不重问；「只要探测报告」→ 要改造：重摆 G3。执行 → `dry_run`：无 `setup\tstarted` 时（已点选的 G4 先追加 `G4\t作废`）追加 `G2\tdry_run` 与 `stop\t2\tdry_run`（不按当前步记）；有 `setup\tstarted` 即已写盘，G5 清理仍要远端执行，不授权就停在步 7 给终态警告并追加 `stop\t7\tG4 后改 dry_run`，不当成从未写盘；之后再改回执行：重过 G2（记 `reauth\tremote_exec`）后按 `恢复点.md` 分支表走，自家产物不当他人产物、产物在时不从步 3 重探，`stop\t7` 之前的 L1 不算。

## G4 之后

别就地打补丁，按「改的是哪个决定 → 回退到哪一步 → 作废哪些产物 → 是否重过 G4 → 必重跑哪道门禁」整条回退；
`setup.sh` 幂等，改完整份重跑，不在远端手工改；换 benchmark / 换模型对 `form.yaml` 的处置同上节（G4 前后共用）。每次回退按 `恢复点.md` 定义的格式在 `PROGRESS` 追加 `rollback→` 行，
并同步改 `form.yaml` 的对应行（出处标签照改）。**setup 正在跑时任何回退**：先等 `EXIT=`，或经用户确认后
`tmux kill-session -t setup-<name>`（无 tmux 时 `kill -- -$(cat /tmp/setup-<name>.pid)` 杀整个进程组，不只杀包装 pid）并在 kill **之前**记 `setup\tkilled`，不并发重跑；换机不被旧机阻塞——不等旧机 setup 出 `EXIT=`，旧机连不上就直接写 `obsolete→`，警告按下表 ① 行。
G4 之后才说「只要探测报告」不当 G3 选项处理：已写盘，按阶段 6 走 G5，或停在步 7 给 SKILL.md「过程反馈」的终态警告。

**回退产生的 `rm`** 一律列进差量 G4：obs/yaml 按盘上与 `form.yaml` 的 benchmark 差集列，改名废目录按 下文「改名」取舍；批准后在重跑 `setup.sh` **之前**执行并追加 `rm done`；没有 `rm done` 不重跑 setup，重跑后 `ls` 出 `form.yaml` 之外的 yaml/obs 不算 `SETUP_OK`；G5 复核发现仍在就回差量 G4，不在 G5 当场删。
**阶段 6 清理之后**的任何回退，完成后都重做阶段 6 并**全部 benchmark** 复跑 L1。

**「重过差量 G4」**：落点、下载项或模型环境变了就出一份**只含变化条目**的计划再过 G4（含要 `rm` 的旧产物）；
只改 yaml/obs 内容、落点不变的标「否」，算原 G4 已批准；改回盘上已落的 benchmark 集合也标「否」，本地重生成的 `setup.sh` sha256 与 `setup_sha256` 不同照样整份重跑、复跑 L1 后才补 `沿用原批准`；已点选未执行的差量 G4 追加 `G4\t作废`。

## 改名

- **当场换名**（G3/G4 时改、未起 setup，不算改名：不劝阻、不写 `rename→`，只同步 `name`，重跑 5d 后重摆 G4）只看实际状态：
  `PROGRESS` 里没有 `setup\tstarted\t<现name>`、现名也不是自跑产物（口径见下条），不看 `/opt/ms-<现name>/` 在不在（为避开他人目录换名不算改名）。其余换名一律按改名：先等旧 setup 出 `EXIT=`（或经确认 kill；自跑产物无 `started`，不等），再追加 `rename→` 与 `rollback→5d`。
- 差量 G4 的 `rm` 只列 `ls -d /opt/ms-* /opt/*-cache /opt/*-env`（不含 `/opt/{uv-bin,uv-python,ray-py,uv-cache}`）里**有 `setup\tstarted\t<该名>`、或属自跑产物（`G4\tdry_run 自跑\t<该名>`，或有 `dry_run` 的 G2/`reauth` 行、`SETUP_INFO.name` 是该名且该名见于本目录 `name`/`rename→`）**的旧名产物；`-env` 仅当 `SETUP_INFO` 有 `env_created_by_setup=1`，无 `SETUP_INFO` 的在 G4 单列让用户点选；
  不列与当前 `name` 同名的（换模型沿用旧名时的 `-env` 除外，见上表）、不列其余无记录的。
- 撤回到当前落盘名不算新改名（与「当场换名」同时命中按本条）：作废未执行（无 `rm done`）的差量 G4（已点选的追加 `G4\t作废`），不删现名目录；已写过 `rename→` 的追加 `rename→<落盘名>\t<被放弃名>` 并改回 `name`；
  盘上没动过、本地 `setup.sh` sha256 与 `setup_sha256` 一致、最后一条 G4 行是批准类或 `沿用原批准`、且没有别的未收口 `rollback→` 时才补 `G4\t沿用原批准`；是 `dry_run 自跑`、从没批准过或无 `SETUP_INFO` 就重摆全量 G4，有别的未收口 `rollback→` 就按 `恢复点.md`「收口」走，都不补。最后一条 `rename→` 之后已有 `rm done` 的不作废、不补，按差量「是」重摆。`EXIT=` 前撤回不留任何记录（已 kill 的按 `恢复点.md` `killed` 行）。

## 资源复用的指纹

`setup.sh` §5 须把**资源来源指纹**
（HF repo 用 repo@revision；本地路径与 ckpt 内 tokenizer 一律用文件内容 sha256，原地覆盖权重才认得出）写进 `SETUP_INFO` 的 `asset_fingerprint=`，
复用前比对：一致才 `ASSET_REUSE:`，不一致就清空 `/opt/<NAME>-cache` 重建并打 `ASSET_REBUILD: 指纹变化`。

## 要点

- **步 8 不是锁**：已给出步 8 命令后再改任何一项（只换 `ckptPath`、换机除外），回到对应行，完成后明确告诉用户「之前给的步 8 命令作废，以本次为准」。当前机 `PROGRESS` **最后一条** `authorized_keys` 是 `删 done` 即连不回去（是 `删` 先按 `恢复点.md` 第 2 步核验） ⇒ 停，请用户在控制台重新放公钥后回 G2，登录成功后追加 `authorized_keys\t留`。
- **回到已作废的旧机**：复用旧目录并追加 `revive`（`name` 与旧目录不同时照写 `rename→`，不省略；`revive` 在重过 G2 后（选 dry_run 也写）、第 3 步查 setup 之前写；目标名取离开的目录的 `name`，`rename→` 时机见上文「改名」）；probe ckpt 的确认不沿用（拷回的也改回 `[探测] … (probe)` 重问）；G4 按全量摆（不按差量），先 `ls` 盘上 yaml/obs 与 `form.yaml` 的 benchmark 集合比对，多出来的与下文「改名」名单里的旧名产物进 `rm`；`[L1]`/`[L3]` 行按离开的目录整行覆盖，离开目录里是 `未提供`/`重核`/`[探测]`/`[查表]` 的行在本目录置 `未提供`（旧 `[L1]` 值不保留）（①、`name`、`history:` 不拷，`prefill_accepted` 清空、`g3_confirmed: false`；离开目录里 `待核` 的行同 `未提供`；`benchmarks` 整集替换，不逐行合并），`[探测]` 行全部重 probe、`[查表]` 行重查，同会话也重过 G2（记 `reauth`）；离开的目录在写 `revive` 时同时追加 `obsolete→`（警告照 ① 行）。
  旧机已有 `step8 delivered` 且其后无 `rollback→`/`rename→` 且拷回值与其 `form.yaml` 一致（含 `name`，不比 `history:` 段）⇒ 不连机、不重探，照写 `revive` 与离开的目录的 `obsolete→` 后原样复述其 `STEP8`；有差异就连机按上条走（G4 仍全量摆），不直接复述。
- **G5 剔除后又要删**：剩余项再过一次 G5，删完复跑 L1。
