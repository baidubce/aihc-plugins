# 脚本模板（自定义镜像 / raw 启动路径）

服务怎么写**以上游 `vla-evaluation-harness` 自带的 `add-model-server` 文档为准**（指模型环境里装的那份
harness 源码/文档，不是当前环境里任何同名可加载 skill），本文只补「平台 raw 启动路径」额外要求的部分：
启动器、端口来源、无默认 ckpt、session 分桶。逐条可验的清单在 `协议自检.md`。

## 两种形态，先选一个

| 形态 | 条件 | 怎么写 |
|---|---|---|
| **A. 复用上游基类**（优先） | 模型环境能装上 `vla_eval`（harness）而不破坏推理栈，且已装版本是 `v0.9.0`（不是时不默认走 A、不在 G4 计划外改装 harness：要按 `v0.9.0` 装就列进 G4 计划 [6]（由用户在 G4「调整计划」定），否则走 B；差异写进 `setup.sh` 的 `HARNESS_DIFF=`） | 子类化 `PredictModelServer`，只实现 `predict` + specs，协议、编解码、chunk、batch 全由基类负责 |
| **B. 自己实现协议** | 装 harness 会和推理栈冲突（常见于老 torch / 魔改 transformers） | 自己起 HTTP + WebSocket，严格按 `协议自检.md` 逐条对 |

A 能走就走 A——协议细节（msgpack `use_bin_type`、`__ndarray__` 递归解码、`__image__` 三种格式、
seq 回显、`ping_interval=None`）自己写一遍极易漏。先在模型环境里试装：

```bash
"$MODEL_ENV/bin/pip" install --dry-run <harness 包或源码路径>   # 看它会不会动 torch/numpy
```

它要改 torch / numpy 大版本就别装，走 B。

## 形态 A：骨架

```python
#!/usr/bin/env python
"""<Model> model server（对齐 harness v0.9.0 的 PredictModelServer API）。"""
from typing import Any

import numpy as np
from vla_eval.model_servers.base import Row, Rows
from vla_eval.model_servers.predict import PredictModelServer
from vla_eval.specs import DimSpec
from vla_eval.types import Action, Observation


class MyModelServer(PredictModelServer):
    """<Model> 推理服务。"""

    def __init__(self, checkpoint: str, chunk_size: int | None = None, **kwargs: Any) -> None:
        """初始化。

        Args:
            checkpoint: 权重路径。**不给默认值**——宁可启动失败，也不要静默加载默认权重跑完全程。
            chunk_size: 每次推理执行的动作步数；None = 每帧都推理。
            kwargs: 透传给基类（只认 max_batch_size / max_wait_time / max_rows，均为关键字参数）。
        """
        super().__init__(chunk_size=chunk_size, **kwargs)
        print(f"[ms] loading checkpoint: {checkpoint}", flush=True)   # 日志里留一次实际路径
        self._policy = load_policy(checkpoint)
        self._warmup()                                               # 必须在开始监听之前
        self._episode_state: dict[int, Any] = {}                     # key = row.id

    def reset_episodes(self, rows: Rows) -> dict[int, Exception] | None:
        """新 episode 开始：按 row.id 清空 per-episode 状态（row.episode.config 是 EPISODE_START 载荷）。"""
        for row in rows:
            self._episode_state[row.id] = None
        return None

    def predict(self, obs: Observation, row: Row) -> Action:
        """单帧推理（row 是该 episode 的行，per-episode 状态用 row.id 取）。

        Returns:
            `{"actions": np.ndarray}`，1-D 单步 `(action_dim,)`；
            返回 2-D `(chunk_size, action_dim)` 时由基类按 episode 缓存逐帧下发。
        """
        ...
        return {"actions": np.asarray(actions, dtype=np.float32)}

    # 逐字抄 benchmark 的 get_action_spec()（robodojo/benchmark.py:431 的 format 串），不要自己改写
    ACTION_FORMAT = "absolute_joint_positions_with_grippers"

    def get_action_spec(self) -> dict[str, DimSpec]:
        """声明 MS 产出的动作。`key` / `dims` / `format` 三项都要与 benchmark 期望对得上。

        `format` 是**自由字符串**（`specs.py` 的 `POSITION_DELTA` / `GRIPPER_CLOSE_POS` 之类常量只是
        便利品，不是闭集），但 harness 会拿它做跨端比对：对不上只产 warning、评测照跑，**分数是错的**。
        见下面「action / observation spec 怎么写」。
        """
        return {
            "actions": DimSpec(
                "actions", 14, self.ACTION_FORMAT,
                description="left arm (6), left gripper (1), right arm (6), right gripper (1)",
            ),
        }

    def get_observation_spec(self) -> dict[str, DimSpec]:
        """声明期望的观测。相机槽位名与 wire 键名是两套命名空间，别在这里混用。"""
        return {
            "cam_high": IMAGE_RGB,          # 模型侧槽位名；wire 键名映射见「观测键名 → 模型槽位」
            "cam_left_wrist": IMAGE_RGB,
            "cam_right_wrist": IMAGE_RGB,
            "state": RAW,                   # 维度不校验时用 RAW / dims=0；要校验就 DimSpec("state", 14, "…")
        }


if __name__ == "__main__":
    from vla_eval.model_servers.serve import run_server

    run_server(MyModelServer)
```

`run_server`（`model_servers/serve.py:525`）用 jsonargparse 按 `__init__` 签名生成参数：`__init__` 参数走
`--args.<key>=<value>`（或 `--config <yaml>` 的 `args:` 子 dict），另有 `--host/--port/--address/--verbose`。
基类参数 `chunk_size` / `max_batch_size` / `max_wait_time` / `max_rows` 的语义见 `model_servers/predict.py:14-20`；
**`action_ensemble` / `ema_alpha` / `SessionContext` 在 v0.9.0 已删除**，照旧版写会在 import 或启动时直接报错。
所有钩子（`reset_episodes` / `predict` / `predict_batch` / `finish_episodes`）跑在**同一个模型线程**上、按到达顺序串行，
`__init__` 在调用方线程：CUDA graph、JAX 这类线程绑定的状态放到首次 `reset_episodes` / `predict` 里建
（上游 `robodojo_pi05.py` 在 `__init__` 里 warmup 能工作，但换框架前先确认它不绑线程）。
批量推理覆写 `predict_batch(obs: Batch, rows: Rows) -> Batch`，并把 `max_batch_size` 调大。

## action / observation spec 怎么写

**spec 不是「写死 ee 或 joint 二选一」**：`get_action_spec()` 返回的是一个 `dict[str, DimSpec]`，
键可以任意命名，段数也不限。benchmark 侧决定了它期望哪几段（`benchmarks/<name>/benchmark.py`
的 `get_action_spec()`），MS 侧照它写。

`DimSpec` 六个字段（`specs.py:38-71`，v0.9.0）：

| 字段 | 怎么用 | 写错的后果 |
|---|---|---|
| `name` | 段名，如 `actions` / `joints` / `position` | 与 benchmark 的 key 对不上 ⇒「benchmark expects it but server doesn't declare it」warning，取动作时可能取不到（behavior_1k 的 wire 键名就固定是 `actions`，见 `评测集观测口径.md` §3.8） |
| `dims` | 这段多少维；`0` = 不校验长度（图像、语言、只关心语义的段）。**必须是 `int`** | 两端都 >0 且不等 ⇒ warning。写成旧写法的 `shape` / `dtype` / `dims=[16]` 会让 `DimSpec.from_dict` 抛 `KeyError`、被 orchestrator 吞成 warning，**维度校验整段失效**（16D 的 `joints` 也会溜过去）；`ms_selfcheck.py` 的 `action_spec.schema` 直接判 FAIL |
| `format` | **语义串**，自由字符串，逐字对齐 benchmark | 不等 ⇒ warning（**最常踩、最不报错的一处**） |
| `range` | `(min, max)`，可交给 `validate()` 查越界/NaN | 只影响本地校验，不影响跨端比对 |
| `accepts` | **消费者侧**声明能接受哪些 format（如 `ROTATION_EULER_ACCEPTS_AA` 接受 `axis_angle`）；设在 `get_action_spec()`（benchmark 是动作的消费者）或 `get_observation_spec()`（MS 是观测的消费者） | MS 侧要放宽入参语义才用它；不设即严格等值 |
| `description` | 段内顺序的自由文本说明 | 不参与比对，但这是唯一能写清「哪 6 维是左臂」的地方 |

四种典型形状：

```python
# ① 单块 14D 双臂绝对关节（robodojo / robotwin 关节模式）：一段，靠 description 说明内部顺序
{"actions": DimSpec("actions", 14, "absolute_joint_positions_with_grippers",
                    description="left arm (6), left gripper (1), right arm (6), right gripper (1)")}
{"joints": DimSpec("joints", 14, "joint_positions")}                 # robotwin

# ② 三段末端增量（libero / simpler / calvin）：position + rotation + gripper 各自独立声明
{"position": POSITION_DELTA, "rotation": ROTATION_AA, "gripper": GRIPPER_CLOSE_POS}      # libero
{"position": POSITION_DELTA, "rotation": ROTATION_EULER, "gripper": GRIPPER_CLOSE_POS}   # simpler

# ③ 多段混合（robocasa365，5 段 13D）：段名不限于 arm/ee
{"position": POSITION_DELTA, "rotation": ROTATION_AA, "gripper": GRIPPER_CLOSE_01,
 "base_motion": BASE_MOTION, "control_mode": CONTROL_MODE_01}

# ④ 单块但内部混语义（robotwin 末端模式 16D / behavior_1k 关节 23D）
{"ee_pose": DimSpec("ee_pose", 16, "dual_eef_pos3_quatwxyz4_gripper1",
                    description="left eef pos (3), left quat wxyz (4), left gripper (1), "
                                "right eef pos (3), right quat wxyz (4), right gripper (1)")}
{"joints": DimSpec("joints", 23, "joint_positions_r1pro")}           # behavior_1k
```

**维度不是由「ee 还是 joint」决定的**：robotwin 的 `joints` 是 14D、`ee_pose` 是 16D，
但 libero / simpler / calvin 的末端是 **7D 拆三段**，robocasa365 是 13D 五段，behavior_1k 的
`joints` 是 **23D**，robodojo 只有 joint 14D 没有末端模式。按「ee=16 / joint=14」的惯性写
一定在某些 benchmark 上错维度——**只能抄 `get_action_spec()` 的值**（见 `评测集观测口径.md` §2）。

段名、段数、维度三者都由 benchmark 定，MS 照抄；模型侧的分段口径（哪几维是左臂、哪几维是夹爪）写在
`description` 与 `接入表单.md` 的 `action_layout` 里，**不要为了匹配 benchmark 的段名去改模型输出顺序**。

**还有一层不在这份 spec 里**：benchmark 的构造参数决定它用哪套口径（robotwin `action_type`、
calvin `absolute_action`）。MS 声明 `ee_pose` 16D 只说明「这是一种可能」，提交评测时 sub_bench
必须真的传 `action_type=ee`——否则 benchmark 走默认 `qpos`，16D 被**静默截断成 14** 跑完全程
（`robotwin/benchmark.py:521-524`，不报错、只出错分数）。自检用
`--bench-param action_type=ee` 才能把这条钉住。

**`format` 必须逐字对齐 benchmark**，三件事一起做：

1. 抄：`git show v0.9.0:src/vla_eval/benchmarks/<name>/benchmark.py | grep -A8 "def get_action_spec"`
2. 核：`ms_selfcheck.py` 的 `action_spec` 用例会拿内置表与 HELLO 声明比一遍，对不上直接 FAIL——
   不要跳过它。benchmark 有构造参数时（robotwin `action_type`、calvin `absolute_action`）再传
   `--benchmark robotwin --bench-param action_type=ee` 把候选收窄到实际那一套，不传只会打提示
3. 冲突不换串：模型实际语义与 benchmark 期望不同（delta vs absolute、夹爪正负、欧拉 vs 轴角）时，
   改 `format` 只是把冲突藏起来，评测照跑、分数是错的。要么在 MS 里做真正的转换，
   要么在 `get_action_spec()` 里用 `accepts` 明确声明可转换关系（消费侧才写 `accepts`），
   要么停下找用户确认——不要靠改串让 warning 消失。

## 形态 B：自己实现时的最小约束

同一端口上同时提供：

- `GET /config` → 200（平台探活；**不是** `/health`）
- WebSocket，msgpack 二进制帧，`compression=None`、`max_size=None`、**显式 `ping_interval=None`**
  （长推理会被库默认心跳误杀）

两条分流/契约上的真机坑：

- **`process_request` 必须按请求头分流，不是按路径**：带 `Upgrade: websocket` 的请求直接 `return None`
  放行握手。BA 连的是无路径 `ws://<pod_ip>:<port>`（`request.path == "/"`），把 `/` 也当 `/config`
  应答会让握手被 HTTP 200 顶掉，客户端报 `server rejected WebSocket connection: HTTP 200`，
  而 `curl /config` 全程正常——症状完全指不到根因。
- **包 subprocess 时，上游的必填字段要去读上游代码确认，不要从默认值推**：DM05 的
  `/v1/infer` 要求 `observation.state` 必填，维度由 `robot_type` 决定（ALOHA = 6 关节+1 夹爪 ×2 = 14），
  漏了会在 warmup 阶段 400 死循环。**缺字段/维度不符要显式抛错，不要补零**——补零会跑完全程并产出
  一个看起来正常的错分数。

per-episode 状态**按 `session_id` 分桶**（多 shard 共享一个 MS），`EPISODE_START` 清空该桶
（形态 A 由基类按 `row.id` 分好，见上；形态 B 要自己做）；
推理异常回 `ERROR{"error": "observation_failed: <Exc>: <msg>"}`，**不关连接、不返零动作**。

其余逐条照 `协议自检.md` 打勾。

### 形态 B 必做：`VECTOR_STEP`（robodojo / ocbench）

这两个 benchmark 是 `VectorStepBenchmark`，客户端**不看** `OBSERVATION`/`ACTION`，只发 `VECTOR_STEP`。
HELLO 不带 `capabilities: {"vector_step": true}` 的后果是致命的：`_run_vector` 开头直接
`raise RuntimeError("... does not take vector steps ...")`，benchmark 侧 `hard_exit` 吞掉异常后
`os._exit(1)` —— 线上只看到 `exit code 1` + 0 episode、没有 traceback，MS 日志只有 connect→close。
其余 benchmark **不要**声明它（客户端不会走这条路，声明了也不会错，但没必要）。

一轮 `VECTOR_STEP` 的 payload（`runners/vector_runner.py` 的实际构造）：

```python
{"ends":   [[slot, {"success": bool, ...}]],      # 要结束的槽位
 "starts": [[slot, {"task": {...}, "recording": {"sid": ..., "eval_id": ...}}]],  # 要新开的槽位
 "slots":  [slot, ...],                            # 本轮要动作的槽位，顺序即回包行序
 "observations": {"images": {"cam_head": arr[rows, H, W, 3], ...},
                  "<state_key>": arr[rows, D],
                  "task_description": [str] * rows}}   # 列式 batch：每列带行维
```

回包：

```python
{"type": "vector_result", "seq": <请求 seq>, "payload": {
    "actions": {"actions": arr[rows', action_dim]},   # rows' = 未失败的 slot，按 slots 顺序
    "errors":  [[slot, "episode_start_failed: ..."], ...]}}
```

语义（`serve.py:_vector_step` 同口径，照做即可）：

1. **顺序是 ends → starts → observations**；结束一个仍在跑的 slot 后立刻用新 `starts` 复用同一槽位是合法的。
2. slot 号是客户端临时编号，**不是** session id；每个 slot 有独立 episode 会话，`starts[slot]` 的 config
   当作该会话的 `EPISODE_START` payload（含 `task` / `recording.sid`）。
3. 某行观测失败 → 该 slot 进 `errors`、**不进** `actions` 的行（回包行数 < len(slots) 是允许的）；
   整轮都失败就回空 `actions`，**不要关连接**。
4. 空 `slots`（只带 `ends` 的收尾轮）也要回一条 `vector_result`。
5. `obs_shapes`：列式 `[rows, ...]`，单槽位是 `[1, H, W, 3]` 而不是 `[H, W, 3]`——按 `obs_spec` 直接
   `np.stack` 即可；不要把单帧观测当 batch 收（切片后形状对不上，模型侧多半不报错、只是全错）。
6. `capabilities.vector_step` 只是准入：HELLO 的 `action_spec` / `observation_spec` 仍必须是
   `name`/`dims`/`format` 的 DimSpec 口径。相机别名表不要塞进 `observation_spec.images`
   （那里只能是 DimSpec，塞成按别名嵌套的 map 会让 `DimSpec.from_dict` 抛 `KeyError('name')`、
   校验被静默吞掉）；放进 HELLO 的另一个键（如 `camera_slots`），harness 不读、也不影响协议。

harness 侧有现成实现可对照：`base.py:supports_vector_step` / `serve.py:_vector_step` /
`runners/vector_runner.py`。`scripts/ms_selfcheck.py` 的 `vector_step` 用例会真发一轮
`starts+observations` 再发一轮 `ends`，验证 capability、行数、动作形状与槽位释放。

## Bearer 鉴权

只在同一个 MS 要以「自建推理服务」接入时需要（平台行为见 `协议自检.md`「自建推理服务鉴权」）。
平台拉起自定义镜像时探 `/config` 不带鉴权头，所以**环境变量里没有 Token 就不鉴权**，同一份代码两条路径都能用。
harness v0.9.0 的 `serve` 没有服务端鉴权，要自己在 `process_request` 前面加一层：

```python
import hmac
import os
from http import HTTPStatus

_TOKEN = os.environ.get("VLA_EVAL_SERVER_TOKEN", "")   # 只从 env 读，不走命令行、不打日志


def _bearer_ok(request) -> bool:
    """/health、/config、WS 握手共用一套校验；compare_digest 防计时侧信道。"""
    got = request.headers.get("Authorization", "").encode()
    return hmac.compare_digest(got, f"Bearer {_TOKEN}".encode())
```

**形态 A**：包一层 harness 的 `_make_process_request`，在 `serve.serve(...)` / `run_server(...)` **之前**替换
（`serve_async` 调用时按模块名取它，替换在启动后不生效）：

```python
from vla_eval.model_servers import serve


def _with_bearer(make):
    def wrapped(model_server):
        inner = make(model_server)

        def process_request(connection, request):
            if not _bearer_ok(request):
                return connection.respond(HTTPStatus.UNAUTHORIZED, "unauthorized\n")
            return inner(connection, request)   # 原逻辑：/health、/config、其余放行握手

        return process_request

    return wrapped


if _TOKEN:
    serve._make_process_request = _with_bearer(serve._make_process_request)
```

`_make_process_request` 是 harness 私有函数，升级 harness 后先用 `ms_selfcheck.py --require-auth` 复验一遍。

**形态 B**：鉴权放在 `process_request` 第一行，排在 `Upgrade` 分流之前：

```python
def process_request(connection, request):
    if _TOKEN and not _bearer_ok(request):
        return connection.respond(HTTPStatus.UNAUTHORIZED, "unauthorized\n")
    if request.headers.get("Upgrade", "").lower() == "websocket":
        return None
    ...
```

- 不通过只回 401（或 403）。回 500 会被平台当成「还在加载」重试到 attach 超时，报错指不到 Token。
- 不要先 101 再在 `HELLO` 里拒：平台探活只认握手状态码，不发 `HELLO`。

## 相机键名映射（两套命名空间，照 harness `_CAMERA_MAP` 抄）

模型内部的相机名（训练口径）与 benchmark 实发的观测键名不是同一套。**不要改模型侧参数去
迁就观测键名**——那个名字往往逐字进模型输入（dm05 的 `--cameras` 同时是上游
`--inference-config.image-prompts`，上游 `label = f"{prompt} image: "`），改了不报错只错分数。
正确做法是加一张别名表，缺则显式报错：

```python
# 每个 key 是**模型侧槽位名**（训练口径，不可改），value 是可接受的观测键名候选。
# ⚠️ 下面的候选是**占位示例**：只留你在 harness 源码里真见过的键名，猜的一律删（见本节末尾）。
CAMERA_ALIASES = {
    "head": ("head", "cam_head", "cam_high", "images_1", "agentview", "top"),
    "left wrist": ("left wrist", "cam_left_wrist", "left_wrist", "images_2", "wrist_left"),
    "right wrist": ("right wrist", "cam_right_wrist", "right_wrist", "images_3", "wrist_right"),
}


def build_slots(self, images: dict) -> dict:
    """把观测里的相机图按模型侧顺序映射成 1-based slot。

    Raises:
        ValueError: 缺相机。**不要兜底补空图**——那会产出看起来正常的错分数。
    """
    if not isinstance(images, dict):
        raise ValueError(f"observation.images 必须是 map，实际 {type(images).__name__}")
    lower = {str(k).strip().lower(): v for k, v in images.items()}
    slots = {}
    for idx, name in enumerate(self.args.cameras):
        key = name.strip().lower()
        val = images.get(name, lower.get(key))
        if val is None:
            for alias in CAMERA_ALIASES.get(key, ()):
                val = lower.get(alias)
                if val is not None:
                    break
        if val is None:
            raise ValueError(
                f"观测缺相机 {name!r}（别名 {list(CAMERA_ALIASES.get(key, ()))}），"
                f"实到 {sorted(map(str, images))}")
        slots[str(idx + 1)] = to_png_base64(np.asarray(val))
    return slots
```

两条配套动作：

- `HELLO` 的 `observation_spec.images` 里把每个槽位的 `accepted_keys` 一并声明出来
  （`ms_selfcheck.py` 会据此在零交集时提示），自检与排障都能少猜一轮。
- state 字段名**按 benchmark 三分**，三个都要兼容：
  `obs.get("state", obs.get("states", obs.get("joint_state")))`，**三个都缺则抛错不补零**。
  （`state`→robodojo；`states`→libero/calvin/behavior1k/simpler；`joint_state`→robotwin 14D 恒发。
  harness v0.9.0 下 robotwin 在 `send_state=True` 时**另发** `states` 16D 末端位姿（与 `joint_state`
  语义不同，别混用）；robocasa 的 `states` 9D 也受 `send_state` 控制、默认不发；robocasa365 发的 `state`
  是**嵌套 dict** 不是向量。对照表见 `评测集观测口径.md` §4。）
  ⚠️ 上游**没有一个 MS 兜全三种**，照抄任何一个都会在某个 benchmark 上静默拿不到 state。
- 图像要取**两层**：`obs["images"][cam]`，顶层只有 `images` / state / `task_description`。

⚠️ **别名只能来自确认过的出处**（`references/评测集观测口径.md` §1 的三个来源）。
上面示例里的候选名是**占位**，不是已核实清单——往表里塞自己猜的别名比不加更危险：
缺键只是报错（看得见），而猜错的别名**命中了另一路相机**（`top` 被当成 head、
`images_2` 实际是右腕）会静默把图喂错槽位，跑完全程产出一份看起来正常的错分数。
只保留你真的在源码里见过的键名，其余删掉，让它以 `ValueError` 失败。

真实键名的来源与「为什么不能改模型侧参数」的完整论证见 `SKILL.md`「阶段 3.5：观测对齐」，
各 benchmark 的实发键名/形状速查见 `评测集观测口径.md`。

## 训练口径接线（⑥C）与历史帧

**这一节决定「有没有分」，L1 自检完全拦不住。** 推理侧默认值与训练值不一致时，服务正常起、
形状全对、日志无错、跑满 `max_steps`，只是分数为 0。三件事必做：

1. **逐项透传给上游 CLI，不要依赖上游默认值**。默认值可以被上游改、也可能语义取反
   （dm05：`use_absolute_action = (action_mode == RELATIVE)`，把训练的 `ABSOLUTE` 传进去才是
   「不再叠 state」）：

   ```python
   argv = [...,
           "--data-config.action-mode", args.action_mode,      # 默认 ABSOLUTE，来自 ⑥C
           ]
   if args.history_slots > 0:                                  # 来自 ⑥C
       argv += ["--data-config.is-history",
                "--inference-config.max-history-images", str(args.history_slots)]
   ```

2. **启动日志把生效口径打一行**（出分后回溯只能靠它）：

   ```python
   print(f"[ms] train口径: action_mode={args.action_mode} "
         f"use_absolute_action={cfg.use_absolute_action} "
         f"is_history={cfg.is_history} max_history_images={cfg.max_history_images} "
         f"history_slot={slot} history_fps={fps}", flush=True)
   ```

3. **历史帧按墙钟网格采，不是按 chunk 采**。训练侧是 `slot=k` 取 `frame_index - k/fps*source_fps`
   的帧（**不含当前帧**、episode 头一秒不足则丢弃缺失槽位），推理侧手上只有观测流，等价做法是
   「上一帧等到满 `1/fps` 才转正」——当前帧永远只进 `pending`，绝不进 `history`：

   ```python
   def push_history(self, head, slots: int, fps: float, now: float) -> None:
       if slots <= 0:
           return
       if self.pending is None:
           self.pending = (now, head); return
       if now - self.pending[0] >= 1.0 / max(fps, 1e-6):
           self.history.append(self.pending[1])          # 最旧在前
           del self.history[:max(0, len(self.history) - slots)]
           self.pending = (now, head)
   ```

   四条不变量：① 必须**每个观测步**采样（放在 chunk 命中之前），chunk 内不采会让 1 FPS 网格整体后移；
   ② 传出去的是 `list(history)`，**不含当前帧**、最旧在前、长度 ≤ 槽位数；
   ③ `EPISODE_START` 清空 `history` 与 `pending`；④ warmup 要用**满槽位数**的 dummy 历史帧跑一次，
   否则首个带满历史的真实推理会再付一次编译开销（可能冲掉首帧 30s 预算）。
   自测：喂 60 帧 @5 Hz，期望每 1 秒 `len(history)` +1、`history[0]` 是最旧、当前帧只在 `pending`。

## 启动器 serve.sh

平台用 `Popen(list)` **非 shell** 启动，命令里的 `$MS_PORT` 不会被展开。
端口可以来自 `{port}` / `{address}` 占位符，也可以由进程内读 `MS_PORT`（平台一定会注入）。
**优先读 `MS_PORT`**：控制台命令里就不必出现端口，少一个能填错的地方。包一层 `bash` 启动器最省事：

```bash
#!/usr/bin/env bash
# /opt/ms-<name>/serve.sh —— 控制台启动命令：
#   bash /opt/ms-<name>/serve.sh --config /opt/ms-<name>/<benchmark>.yaml --ckpt <挂载路径>
# 端口来自平台注入的 MS_PORT；本机手动起时可用「纯数字的第一个位置参数」覆盖。
# 注意：MODEL_ENV 这一行由 setup.sh 写入（`sed`/heredoc 替换），不要两边各写一遍。
set -euo pipefail
MS_DIR=/opt/ms-<name>
MODEL_ENV="@MODEL_ENV@"                     # setup.sh 里体检判出的那个环境，绝对路径
[ -x "$MODEL_ENV/bin/python" ] || { echo "解释器不存在：$MODEL_ENV/bin/python" >&2; exit 2; }
PORT="${MS_PORT:-}"
# 只有第一个参数是纯数字时才当端口并吃掉它；否则原样留给 server.py
if [[ "${1:-}" =~ ^[0-9]+$ ]]; then PORT="$1"; shift; fi
[ -n "${PORT}" ] || { echo "端口未知：平台应注入 MS_PORT；本机手动起请传纯数字第一参数" >&2; exit 2; }
# --config 选 benchmark；没传时只在「恰好一份 benchmark yaml」时默认读它（_ 开头的是共享基座，不算）
CONFIG=""
for a in "$@"; do case "$a" in --config|--config=*) CONFIG=given ;; esac; done
if [ -z "$CONFIG" ]; then
  shopt -s nullglob
  CANDS=()
  for f in "$MS_DIR"/*.yaml; do case "$(basename "$f")" in _*) ;; *) CANDS+=("$f") ;; esac; done
  [ "${#CANDS[@]}" = 1 ] || {
    echo "未传 --config，且 $MS_DIR 下 benchmark yaml 有 ${#CANDS[@]} 份（${CANDS[*]:-无}），不猜：请显式 --config <path>" >&2
    exit 2; }
  set -- --config "${CANDS[0]}" "$@"
fi
exec "$MODEL_ENV/bin/python" "$MS_DIR/server.py" \
  --host 0.0.0.0 --port "$PORT" "$@"
```

- **不要无条件 `shift`**，也不要写 `PORT="${1:-${MS_PORT:-}}"`：那种写法把第一个参数一律当端口。
  控制台命令里一旦漏了 `{port}`，`PORT` 会变成 `--ckpt`、`shift` 又吃掉它，拼出 `--port --ckpt <路径>`，
  argparse 报 `argument --port: expected one argument` 直接 rc=2，日志里只说 `ModelServer exited
  prematurely`，看着像服务坏了、实则命令少写一个词。用 `^[0-9]+$` 判一下就对这类漏写免疫。真机踩过。
- **别写成 `PORT="${1:-${MS_PORT:?端口未传入：用 {port} 占位符}}"`**：`${VAR:?msg}` 的 msg 里出现 `}`
  会提前闭合参数展开，剩下的 `}` 变字面量，`PORT` 成了 `18000}`，服务起不来且报错指向 `--port`
  而不是启动器。真机踩过。
- **解释器路径只有一个来源**：`setup.sh` 里的 `MODEL_ENV`。别在 `serve.sh` 里另写一个 `/opt/<name>-env`
  这类猜测值——改造机上模型环境常在 `/root/miniconda3/envs/<env>`，两处写法不一致时
  `serve.sh` 会在平台上以「解释器不存在」失败，而开发机自检时却是好的（因为自检直接调了对的那个）。
  启动时的 `[ -x ]` 校验就是为了让这类错配在**第一秒**失败，而不是等到 `/config` 探活超时 900s。
- 用绝对路径调解释器，**不 `conda activate`、不依赖 PATH 与 `$HOME`**（运行时用户/HOME 可能不同）。
- `exec` 让 python 接管 PID，平台 kill 时信号直达，不留僵尸。
- 监听 `0.0.0.0`，不能只听 `127.0.0.1`（BA 在另一个 Pod 连 `ws://<pod_ip>:<port>`）。
- **`--config` 缺省只在「恰好一份 benchmark yaml」时成立**：多份而没传就 rc=2 并列出候选，不按字典序、
  不按修改时间挑一份——挑错了 benchmark 会按另一套键名/state 口径跑完全程，产出一份看起来正常的错分数。

## 多 benchmark 配置

一个 benchmark 一份 yaml（为什么不写一份自适应配置见 `SKILL.md`「多选了 N 个 benchmark」）。
N = 1 也照此落一份，口径统一。形状**对齐上游 harness `v0.9.0` 的既有约定**，不自创：

| 上游（`v0.9.0` = `8798464`） | 本 skill 的落点 |
|---|---|
| `configs/model_servers/xvla/_base.yaml`（共享项） | `/opt/ms-<name>/_base.yaml` |
| `configs/model_servers/xvla/{libero,calvin,robotwin,…}.yaml`（`extends: _base.yaml` + 差异） | `/opt/ms-<name>/<benchmark>.yaml` × N |
| benchmark 侧的真实观测形状 | `/opt/ms-<name>/obs.<benchmark>.json` × N（L1 `--obs-spec` 用） |

解析语义照上游：

- `extends: _base.yaml`（相对本 yaml 所在目录）+ `args:`，由 OmegaConf 合并，`${oc.env:VAR,default}` 可插值
  —— `src/vla_eval/cli/config_loader.py:11 load_config`。
- `args:` 里 `port` / `host` 属于服务器层，其余才是 `__init__` 参数 —— `src/vla_eval/cli/main.py:257 _SERVER_LEVEL_KEYS`、
  `:271 _build_serve_cmd`（`vla-eval serve` 先 `load_config` 合并好，再拆成 `--args.<key>=<v>` 传给脚本）。
- ⚠️ **不能直接把 yaml 交给 `run_server` 的 `--config`**：它是 jsonargparse 的 `ActionConfigFile`
  （`src/vla_eval/model_servers/serve.py:535`），**不认 `extends`**（`extends` 只在 `config_loader` 里处理）。
  所以 `server.py` 自己的入口先过 `load_config`
  再起服务（形态 A 写法如下；形态 B 装不了 harness 时自己实现 `extends` 合并，**遇到 `${` 直接报错**，不半解析）：

```python
def main() -> None:
    """入口：yaml 选 benchmark 口径，ckpt 只从命令行取。"""
    import argparse

    from vla_eval.cli import config_loader
    from vla_eval.model_servers import serve

    p = argparse.ArgumentParser()
    p.add_argument("--config", required=True)
    p.add_argument("--ckpt", required=True)            # 无默认值
    p.add_argument("--host", default="0.0.0.0")
    p.add_argument("--port", type=int, required=True)  # serve.sh 从 MS_PORT 传入
    a = p.parse_args()
    kwargs = dict(config_loader.load_config(a.config).get("args") or {})
    for k in ("port", "host"):                          # 服务器层，端口只认 MS_PORT
        kwargs.pop(k, None)
    if "checkpoint" in kwargs:
        raise ValueError(f"{a.config} 里不许写 checkpoint：权重只经 --ckpt 传入")
    print(f"[ms] config: {a.config}", flush=True)      # 日志里留一次实际选中的 benchmark
    if _TOKEN:                                          # 可选：自建推理服务鉴权，见「Bearer 鉴权」
        serve._make_process_request = _with_bearer(serve._make_process_request)
    serve.serve(MyModelServer(checkpoint=a.ckpt, **kwargs), host=a.host, port=a.port)
```

这个 `main()` 取代形态 A 骨架末尾的 `run_server(MyModelServer)`。yaml `args:` 里的每个键（下例的 `obs_spec` /
`state_key` / `state_dim` / `cameras`）都必须是 `MyModelServer.__init__` **显式声明**的参数，不要靠 `**kwargs`
透传给基类——基类不认的键会在启动时 `TypeError`，而拼错的键若被吞掉就等于没配。

每份 `<benchmark>.yaml` 至少写死这些**按 benchmark 变化**的量，其余共享项进 `_base.yaml`：

```yaml
# /opt/ms-<name>/robodojo.yaml
extends: _base.yaml
args:
  obs_spec: /opt/ms-<name>/obs.robodojo.json   # L1 与运行时同一份，避免两套口径
  state_key: state                             # robodojo 单数；libero 系是 states；robotwin 是 joint_state
  state_dim: 14
  cameras: {base: [cam_head], left_wrist: [cam_left_wrist], right_wrist: [cam_right_wrist]}
```

- `cameras` 的 key 是**模型侧槽位名**（训练口径，逐字进模型输入，不可改），value 是该槽位可接受的 wire 键名候选，
  形状同上游 `src/vla_eval/model_servers/robodojo_pi05.py:69 _CAMERA_MAP`；取值就是 `接入表单.md` 的
  `camera_slot_map`，候选只能来自「相机键名映射」一节说的可信出处。示例键名随模型而变，照抄即错。
- **yaml 里不写 `checkpoint`**（上面入口会拒）：权重只经 `--ckpt` 传入，规则同 `接入表单.md` ③。
  `接入表单.md` ③ 的 `ckpt_mode`（复用 / 分别指定）只体现在 `SKILL.md` 步 8 那 N 条命令的 `--ckpt` 是否相同；
  yaml 一旦带了开发机路径，就成了烘进镜像的默认权重。
- `state_key` 写死该 benchmark 实发的那一个（`评测集观测口径.md` §4），MS 优先按它取；
  「相机键名映射」一节的三者兼容写法只作后备，**全缺抛错不补零**。

## 控制台怎么填

| 字段 | 值 |
|---|---|
| image | 控制台「开发机 → 保存为镜像」完成后显示的镜像地址（带新 tag） |
