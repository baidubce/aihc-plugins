# 脚本模板（自定义镜像 / raw 启动路径）

服务怎么写**以上游 `vla-evaluation-harness` 自带的 `add-model-server` 文档为准**（指模型环境里装的那份
harness 源码/文档，不是当前环境里任何同名可加载 skill），本文只补「平台 raw 启动路径」额外要求的部分：
启动器、端口来源、无默认 ckpt、session 分桶。逐条可验的清单在 `协议自检.md`。

## 两种形态，先选一个

| 形态 | 条件 | 怎么写 |
|---|---|---|
| **A. 复用上游基类**（优先） | 模型环境能装上 `vla_eval`（harness）而不破坏推理栈，且已装版本是 `v0.5.0`（不是时不默认走 A、不在 G4 计划外改装 harness：要按 `v0.5.0` 装就列进 G4 计划 [6]（由用户在 G4「调整计划」定），否则走 B；差异写进 `setup.sh` 的 `HARNESS_DIFF=`） | 子类化 `PredictModelServer`，只实现 `predict` + specs，协议、编解码、chunk、batch 全由基类负责 |
| **B. 自己实现协议** | 装 harness 会和推理栈冲突（常见于老 torch / 魔改 transformers） | 自己起 HTTP + WebSocket，严格按 `协议自检.md` 逐条对 |

A 能走就走 A——协议细节（msgpack `use_bin_type`、`__ndarray__` 递归解码、`__image__` 三种格式、
seq 回显、`ping_interval=None`）自己写一遍极易漏。先在模型环境里试装：

```bash
"$MODEL_ENV/bin/pip" install --dry-run <harness 包或源码路径>   # 看它会不会动 torch/numpy
```

它要改 torch / numpy 大版本就别装，走 B。

## 形态 A：骨架

```python
#!/usr/bin/env python
"""<Model> model server。"""
from typing import Any

import numpy as np
from vla_eval.model_servers.base import SessionContext
from vla_eval.model_servers.predict import PredictModelServer
from vla_eval.specs import DimSpec
from vla_eval.types import Action, Observation


class MyModelServer(PredictModelServer):
    """<Model> 推理服务。"""

    def __init__(self, checkpoint: str, **kwargs: Any) -> None:
        """初始化。

        Args:
            checkpoint: 权重路径。**不给默认值**——宁可启动失败，也不要静默加载默认权重跑完全程。
            kwargs: 透传给基类（chunk_size / action_ensemble / max_batch_size …）。
        """
        super().__init__(**kwargs)
        print(f"[ms] loading checkpoint: {checkpoint}", flush=True)   # 日志里留一次实际路径
        self._policy = load_policy(checkpoint)
        self._warmup()                                               # 必须在开始监听之前

    def predict(self, obs: Observation, ctx: SessionContext) -> Action:
        """单帧推理。

        Returns:
            `{"actions": np.ndarray}`，1-D 单步 `(action_dim,)`；
            返回 2-D `(chunk_size, action_dim)` 时由基类缓存逐帧 pop。
        """
        ...
        return {"actions": np.asarray(actions, dtype=np.float32)}

    def get_action_spec(self) -> dict[str, DimSpec]:
        """声明动作维度。"""
        ...

    def get_observation_spec(self) -> dict[str, DimSpec]:
        """声明期望的观测。"""
        ...


if __name__ == "__main__":
    from vla_eval.model_servers.serve import run_server

    run_server(MyModelServer)
```

`run_server` 会按 `__init__` 签名自动生成 argparse，并附加 `--host/--port/--address/--verbose`。
`chunk_size` / `action_ensemble` / `ema_alpha` / `max_batch_size` / `max_wait_time` 的语义见上游文档。

## 形态 B：自己实现时的最小约束

同一端口上同时提供：

- `GET /config` → 200（平台探活；**不是** `/health`）
- WebSocket，msgpack 二进制帧，`compression=None`、`max_size=None`、**显式 `ping_interval=None`**
  （长推理会被库默认心跳误杀）

两条分流/契约上的真机坑：

- **`process_request` 必须按请求头分流，不是按路径**：带 `Upgrade: websocket` 的请求直接 `return None`
  放行握手。BA 连的是无路径 `ws://<pod_ip>:<port>`（`request.path == "/"`），把 `/` 也当 `/config`
  应答会让握手被 HTTP 200 顶掉，客户端报 `server rejected WebSocket connection: HTTP 200`，
  而 `curl /config` 全程正常——症状完全指不到根因。
- **包 subprocess 时，上游的必填字段要去读上游代码确认，不要从默认值推**：DM05 的
  `/v1/infer` 要求 `observation.state` 必填，维度由 `robot_type` 决定（ALOHA = 6 关节+1 夹爪 ×2 = 14），
  漏了会在 warmup 阶段 400 死循环。**缺字段/维度不符要显式抛错，不要补零**——补零会跑完全程并产出
  一个看起来正常的错分数。

per-episode 状态**按 `session_id` 分桶**（多 shard 共享一个 MS），`EPISODE_START` 清空该桶；
推理异常回 `ERROR{"error": "observation_failed: <Exc>: <msg>"}`，**不关连接、不返零动作**。

其余逐条照 `协议自检.md` 打勾。

## 相机键名映射（两套命名空间，照 harness `_CAMERA_MAP` 抄）

模型内部的相机名（训练口径）与 benchmark 实发的观测键名不是同一套。**不要改模型侧参数去
迁就观测键名**——那个名字往往逐字进模型输入（dm05 的 `--cameras` 同时是上游
`--inference-config.image-prompts`，上游 `label = f"{prompt} image: "`），改了不报错只错分数。
正确做法是加一张别名表，缺则显式报错：

```python
# 每个 key 是**模型侧槽位名**（训练口径，不可改），value 是可接受的观测键名候选。
# ⚠️ 下面的候选是**占位示例**：只留你在 harness 源码里真见过的键名，猜的一律删（见本节末尾）。
CAMERA_ALIASES = {
    "head": ("head", "cam_head", "cam_high", "images_1", "agentview", "top"),
    "left wrist": ("left wrist", "cam_left_wrist", "left_wrist", "images_2", "wrist_left"),
    "right wrist": ("right wrist", "cam_right_wrist", "right_wrist", "images_3", "wrist_right"),
}


def build_slots(self, images: dict) -> dict:
    """把观测里的相机图按模型侧顺序映射成 1-based slot。

    Raises:
        ValueError: 缺相机。**不要兜底补空图**——那会产出看起来正常的错分数。
    """
    if not isinstance(images, dict):
        raise ValueError(f"observation.images 必须是 map，实际 {type(images).__name__}")
    lower = {str(k).strip().lower(): v for k, v in images.items()}
    slots = {}
    for idx, name in enumerate(self.args.cameras):
        key = name.strip().lower()
        val = images.get(name, lower.get(key))
        if val is None:
            for alias in CAMERA_ALIASES.get(key, ()):
                val = lower.get(alias)
                if val is not None:
                    break
        if val is None:
            raise ValueError(
                f"观测缺相机 {name!r}（别名 {list(CAMERA_ALIASES.get(key, ()))}），"
                f"实到 {sorted(map(str, images))}")
        slots[str(idx + 1)] = to_png_base64(np.asarray(val))
    return slots
```

两条配套动作：

- `HELLO` 的 `observation_spec.images` 里把每个槽位的 `accepted_keys` 一并声明出来
  （`ms_selfcheck.py` 会据此在零交集时提示），自检与排障都能少猜一轮。
- state 字段名**按 benchmark 三分**，三个都要兼容：
  `obs.get("state", obs.get("states", obs.get("joint_state")))`，**三个都缺则抛错不补零**。
  （`state`→robodojo；`states`→libero/calvin/behavior1k/simpler；`joint_state`→robotwin。
  robocasa 在 harness v0.5.0 不发 state、v0.8.0 起发 `states` 9D；robocasa365 发的 `state`
  是**嵌套 dict** 不是向量。对照表见 `评测集观测口径.md` §4。）
  ⚠️ 上游**没有一个 MS 兜全三种**，照抄任何一个都会在某个 benchmark 上静默拿不到 state。
- 图像要取**两层**：`obs["images"][cam]`，顶层只有 `images` / state / `task_description`。

⚠️ **别名只能来自确认过的出处**（`references/评测集观测口径.md` §1 的三个来源）。
上面示例里的候选名是**占位**，不是已核实清单——往表里塞自己猜的别名比不加更危险：
缺键只是报错（看得见），而猜错的别名**命中了另一路相机**（`top` 被当成 head、
`images_2` 实际是右腕）会静默把图喂错槽位，跑完全程产出一份看起来正常的错分数。
只保留你真的在源码里见过的键名，其余删掉，让它以 `ValueError` 失败。

真实键名的来源与「为什么不能改模型侧参数」的完整论证见 `SKILL.md`「阶段 3.5：观测对齐」，
各 benchmark 的实发键名/形状速查见 `评测集观测口径.md`。

## 启动器 serve.sh

平台用 `Popen(list)` **非 shell** 启动，命令里的 `$MS_PORT` 不会被展开。
端口可以来自 `{port}` / `{address}` 占位符，也可以由进程内读 `MS_PORT`（平台一定会注入）。
**优先读 `MS_PORT`**：控制台命令里就不必出现端口，少一个能填错的地方。包一层 `bash` 启动器最省事：

```bash
#!/usr/bin/env bash
# /opt/ms-<name>/serve.sh —— 控制台启动命令：
#   bash /opt/ms-<name>/serve.sh --config /opt/ms-<name>/<benchmark>.yaml --ckpt <挂载路径>
# 端口来自平台注入的 MS_PORT；本机手动起时可用「纯数字的第一个位置参数」覆盖。
# 注意：MODEL_ENV 这一行由 setup.sh 写入（`sed`/heredoc 替换），不要两边各写一遍。
set -euo pipefail
MS_DIR=/opt/ms-<name>
MODEL_ENV="@MODEL_ENV@"                     # setup.sh 里体检判出的那个环境，绝对路径
[ -x "$MODEL_ENV/bin/python" ] || { echo "解释器不存在：$MODEL_ENV/bin/python" >&2; exit 2; }
PORT="${MS_PORT:-}"
# 只有第一个参数是纯数字时才当端口并吃掉它；否则原样留给 server.py
if [[ "${1:-}" =~ ^[0-9]+$ ]]; then PORT="$1"; shift; fi
[ -n "${PORT}" ] || { echo "端口未知：平台应注入 MS_PORT；本机手动起请传纯数字第一参数" >&2; exit 2; }
# --config 选 benchmark；没传时只在「恰好一份 benchmark yaml」时默认读它（_ 开头的是共享基座，不算）
CONFIG=""
for a in "$@"; do case "$a" in --config|--config=*) CONFIG=given ;; esac; done
if [ -z "$CONFIG" ]; then
  shopt -s nullglob
  CANDS=()
  for f in "$MS_DIR"/*.yaml; do case "$(basename "$f")" in _*) ;; *) CANDS+=("$f") ;; esac; done
  [ "${#CANDS[@]}" = 1 ] || {
    echo "未传 --config，且 $MS_DIR 下 benchmark yaml 有 ${#CANDS[@]} 份（${CANDS[*]:-无}），不猜：请显式 --config <path>" >&2
    exit 2; }
  set -- --config "${CANDS[0]}" "$@"
fi
exec "$MODEL_ENV/bin/python" "$MS_DIR/server.py" \
  --host 0.0.0.0 --port "$PORT" "$@"
```

- **不要无条件 `shift`**，也不要写 `PORT="${1:-${MS_PORT:-}}"`：那种写法把第一个参数一律当端口。
  控制台命令里一旦漏了 `{port}`，`PORT` 会变成 `--ckpt`、`shift` 又吃掉它，拼出 `--port --ckpt <路径>`，
  argparse 报 `argument --port: expected one argument` 直接 rc=2，日志里只说 `ModelServer exited
  prematurely`，看着像服务坏了、实则命令少写一个词。用 `^[0-9]+$` 判一下就对这类漏写免疫。真机踩过。
- **别写成 `PORT="${1:-${MS_PORT:?端口未传入：用 {port} 占位符}}"`**：`${VAR:?msg}` 的 msg 里出现 `}`
  会提前闭合参数展开，剩下的 `}` 变字面量，`PORT` 成了 `18000}`，服务起不来且报错指向 `--port`
  而不是启动器。真机踩过。
- **解释器路径只有一个来源**：`setup.sh` 里的 `MODEL_ENV`。别在 `serve.sh` 里另写一个 `/opt/<name>-env`
  这类猜测值——改造机上模型环境常在 `/root/miniconda3/envs/<env>`，两处写法不一致时
  `serve.sh` 会在平台上以「解释器不存在」失败，而开发机自检时却是好的（因为自检直接调了对的那个）。
  启动时的 `[ -x ]` 校验就是为了让这类错配在**第一秒**失败，而不是等到 `/config` 探活超时 900s。
- 用绝对路径调解释器，**不 `conda activate`、不依赖 PATH 与 `$HOME`**（运行时用户/HOME 可能不同）。
- `exec` 让 python 接管 PID，平台 kill 时信号直达，不留僵尸。
- 监听 `0.0.0.0`，不能只听 `127.0.0.1`（BA 在另一个 Pod 连 `ws://<pod_ip>:<port>`）。
- **`--config` 缺省只在「恰好一份 benchmark yaml」时成立**：多份而没传就 rc=2 并列出候选，不按字典序、
  不按修改时间挑一份——挑错了 benchmark 会按另一套键名/state 口径跑完全程，产出一份看起来正常的错分数。

## 多 benchmark 配置

一个 benchmark 一份 yaml（为什么不写一份自适应配置见 `SKILL.md`「多选了 N 个 benchmark」）。
N = 1 也照此落一份，口径统一。形状**对齐上游 harness `v0.5.0` 的既有约定**，不自创：

| 上游（`0fac650`） | 本 skill 的落点 |
|---|---|
| `configs/model_servers/xvla/_base.yaml`（共享项） | `/opt/ms-<name>/_base.yaml` |
| `configs/model_servers/xvla/{libero,calvin,robotwin,…}.yaml`（`extends: _base.yaml` + 差异） | `/opt/ms-<name>/<benchmark>.yaml` × N |
| benchmark 侧的真实观测形状 | `/opt/ms-<name>/obs.<benchmark>.json` × N（L1 `--obs-spec` 用） |

解析语义照上游：

- `extends: _base.yaml`（相对本 yaml 所在目录）+ `args:`，由 OmegaConf 合并，`${oc.env:VAR,default}` 可插值
  —— `src/vla_eval/cli/config_loader.py:11 load_config`。
- `args:` 里 `port` / `host` 属于服务器层，其余才是 `__init__` 参数 —— `src/vla_eval/cli/main.py:449 _SERVER_LEVEL_KEYS`、
  `:463 _build_serve_cmd`。
- ⚠️ **不能直接把 yaml 交给 `run_server` 的 `--config`**：它是 jsonargparse 的 `ActionConfigFile`
  （`src/vla_eval/model_servers/serve.py:366`），**不认 `extends`**。所以 `server.py` 自己的入口先过 `load_config`
  再起服务（形态 A 写法如下；形态 B 装不了 harness 时自己实现 `extends` 合并，**遇到 `${` 直接报错**，不半解析）：

```python
def main() -> None:
    """入口：yaml 选 benchmark 口径，ckpt 只从命令行取。"""
    import argparse

    from vla_eval.cli import config_loader
    from vla_eval.model_servers import serve

    p = argparse.ArgumentParser()
    p.add_argument("--config", required=True)
    p.add_argument("--ckpt", required=True)            # 无默认值
    p.add_argument("--host", default="0.0.0.0")
    p.add_argument("--port", type=int, required=True)  # serve.sh 从 MS_PORT 传入
    a = p.parse_args()
    kwargs = dict(config_loader.load_config(a.config).get("args") or {})
    for k in ("port", "host"):                          # 服务器层，端口只认 MS_PORT
        kwargs.pop(k, None)
    if "checkpoint" in kwargs:
        raise ValueError(f"{a.config} 里不许写 checkpoint：权重只经 --ckpt 传入")
    print(f"[ms] config: {a.config}", flush=True)      # 日志里留一次实际选中的 benchmark
    serve.serve(MyModelServer(checkpoint=a.ckpt, **kwargs), host=a.host, port=a.port)
```

这个 `main()` 取代形态 A 骨架末尾的 `run_server(MyModelServer)`。yaml `args:` 里的每个键（下例的 `obs_spec` /
`state_key` / `state_dim` / `cameras`）都必须是 `MyModelServer.__init__` **显式声明**的参数，不要靠 `**kwargs`
透传给基类——基类不认的键会在启动时 `TypeError`，而拼错的键若被吞掉就等于没配。

每份 `<benchmark>.yaml` 至少写死这些**按 benchmark 变化**的量，其余共享项进 `_base.yaml`：

```yaml
# /opt/ms-<name>/robodojo.yaml
extends: _base.yaml
args:
  obs_spec: /opt/ms-<name>/obs.robodojo.json   # L1 与运行时同一份，避免两套口径
  state_key: state                             # robodojo 单数；libero 系是 states；robotwin 是 joint_state
  state_dim: 14
  cameras: {base: [cam_head], left_wrist: [cam_left_wrist], right_wrist: [cam_right_wrist]}
```

- `cameras` 的 key 是**模型侧槽位名**（训练口径，逐字进模型输入，不可改），value 是该槽位可接受的 wire 键名候选，
  形状同上游 `src/vla_eval/model_servers/robodojo_pi05.py:70 _CAMERA_MAP`；取值就是 `接入表单.md` 的
  `camera_slot_map`，候选只能来自「相机键名映射」一节说的可信出处。示例键名随模型而变，照抄即错。
- **yaml 里不写 `checkpoint`**（上面入口会拒）：权重只经 `--ckpt` 传入，规则同 `接入表单.md` ③。
  `接入表单.md` ③ 的 `ckpt_mode`（复用 / 分别指定）只体现在 `SKILL.md` 步 8 那 N 条命令的 `--ckpt` 是否相同；
  yaml 一旦带了开发机路径，就成了烘进镜像的默认权重。
- `state_key` 写死该 benchmark 实发的那一个（`评测集观测口径.md` §4），MS 优先按它取；
  「相机键名映射」一节的三者兼容写法只作后备，**全缺抛错不补零**。

## 控制台怎么填

| 字段 | 值 |
|---|---|
| image | 控制台「开发机 → 保存为镜像」完成后显示的镜像地址（带新 tag） |
| command | `bash /opt/ms-<name>/serve.sh --config /opt/ms-<name>/<benchmark>.yaml --ckpt <平台挂载路径>`，**每个 benchmark 一条**（端口由平台注入的 `MS_PORT` 提供，命令里不必出现；只有一份 yaml 时 `--config` 可省） |
| ckptPath | 必填 |
| envs | 需要 HF 栈时自己给 `HF_HOME` / `HF_HUB_OFFLINE=1` / **可写的** `HF_MODULES_CACHE` |

两条会被直接拒绝/报错的写法：

- **写死端口**：`--port 8000`、`IP:端口`、`--address host:8000` —— 控制面校验直接 400。
- **envs 命中黑名单**：`EVAL_*`、`CUDA_VISIBLE_DEVICES`、`RAY_*`、`PYTHONPATH`、`MS_PORT`、代理变量 —— 400。

## 自测顺序

```bash
B=<benchmark>                                # 多选时每个 benchmark 各来一遍
MS_PORT=8000 bash /opt/ms-<name>/serve.sh --config /opt/ms-<name>/$B.yaml --ckpt <ckpt> &
curl -s localhost:8000/config

# 主路径：协议级自动冒烟（零 harness 依赖，逐条 PASS/FAIL）
"$MODEL_ENV/bin/python" <skill目录>/scripts/ms_selfcheck.py \
  --url ws://127.0.0.1:8000 --obs-spec /opt/ms-<name>/obs.$B.json

vla-eval test -c <server-config>.yaml      # 可选：有 harness 时交叉验证，不替代上一步
```

然后按 `开发机改造.md`「自检」以 `env -i` + 死代理口径复跑，逐条对照 `协议自检.md`。
