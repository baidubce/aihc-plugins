# 协议自检（用户自定义镜像）

本文是 policy protocol（`protocol_version = 1`）的逐条可验版，外加平台 raw 启动路径的实际行为。
用 harness `PredictModelServer` 实现的服务天然满足协议段（`脚本模板.md` 形态 A），
只需过「平台侧」与「启动」两段；自己实现协议（形态 B）则要整篇逐条打勾。

## 哪些条目已被脚本自动判定

打勾不靠肉眼：下表的条目由 `scripts/ms_selfcheck.py` 对着**跑起来的 MS** 自动验（用例名就是失败时打出来的 tag），
平台侧的 Ray 条目由 `scripts/ray_env_check.sh` 验。**先跑脚本，再人工过剩下的。**

| 脚本用例 | 覆盖的条目 |
|---|---|
| `obs_spec` | **口径门禁**：`--obs-spec` 必须给（缺省即 FAIL）；每路 shape 是 `[H, W, C]` 正整数且 `C∈{1,3,4}`；`states` 是显式整数；`task_description` 非空 |
| `token_format` | 给了 Token 时按控制面规则校验：不带 `Bearer ` 前缀、长度 16–4096 字节、字符集 `[A-Za-z0-9-._~+/]+=*`、地址是 `ws://`/`wss://`、无 userinfo/fragment、query 不带 `token`/`access_token`/`auth`/`key`；`--require-auth` 下没给 Token 直接 FAIL |
| `config` | `GET /config` 200；`GET /config?max_batch_size=1` 仍 200 |
| `auth` | 只在给了 Token 时跑，复刻数据面探活：带 Token 的 `/health`→`/config` 有一个 200、带 Token 握手 101；**不带 Token、错 Token 握手都必须 401/403**（101 = 没校验，5xx = 会被平台当未就绪重试到超时） |
| `hello` | 信封四字段、`seq` 回显、`protocol_version: 1`、`model_server` 非空；`action_spec` / `observation_spec` 每项是 v0.9.0 的 `name`/`dims`/`format`（写成 `shape`/`dtype` 即 FAIL，见「消息语义」第一条）；声明的相机键名（HELLO 的 `camera_slots`，缺省时看 `observation_spec.images`）与将发送的键名零交集时打 INFO |
| `action_spec` | **动作口径门禁**，三条子断言：`declared`（HELLO 必须声明非空 `action_spec`）、`schema`（每段是 `name` + **整数** `dims` + `format`；写成旧写法 `shape`/`dtype` 即 FAIL——`dims` 缺失会让下面的维度比对被跳过，16D 的段就溜过去了）、`compatible`（与目标 benchmark 的 `get_action_spec()` 兼容，算法同 harness `is_compatible()`：benchmark 要的段缺失即不兼容；`accepts` 存在查成员，否则 `format` 等值，`format` 相同才比 `dims`）。内置表覆盖 robodojo / robotwin / libero(含 `_pro`/`_plus`/`_mem`) / calvin / simpler / robocasa / robocasa365 / behavior_1k 的 v0.9.0 口径，**表外名字只提示人工核、不判 FAIL**。robotwin 的 `action_type`、calvin 的 `absolute_action` 决定实际用哪套口径：不传 `--bench-param` 只打提示，传了就把候选收窄到那一套（robotwin 默认 `qpos` 时 16D 的 `ee_pose` 会被静默截断成 14 跑完全程，`benchmark.py:521-524`），传了不认识/拼错的参数名直接 FAIL。harness 侧 mismatch 只产 warning、评测照跑，所以这条没拦住就等于交付了一份静默错分数 |
| `inference` | 首帧 < 30s（可调）、一问一答、`ACTION` 是 `__ndarray__` 编码的 1-D 有限值且与 `action_spec` 维度一致、两个 episode 串行不报错 |
| `vector_step` | `capabilities.vector_step` 是否声明（robodojo / ocbench 未声明即 FAIL，其余 benchmark 不声明才对）；声明时真发一轮 `starts+observations` 与一轮 `ends`，验 `vector_result`、`seq` 回显、`actions` 行数=槽位数、形状 `(rows, action_dim)`、落位释放 |
| `image_formats` | `__image__` 的 `raw` / `jpeg` / `png` 与裸 `__ndarray__` 四种都能解 |
| `error_resilience` | 畸形观测回 `ERROR`（或可解释的 ACTION）、**不关连接**、下一帧能恢复 |
| `no_episode_context` | 无 episode 上下文的 `OBSERVATION` 不崩（惰性建或回 ERROR） |
| `session_isolation` | 双连接并发、各带不同 `recording.sid` 都能拿到合法 ACTION |
| `ray_env_check.sh` | 下文「平台侧」前 4 条 |

脚本**验不到**的（必须人工）：ckpt 路径与日志核对、**`obs.<benchmark>.json` 里的相机键名是否真等于目标 benchmark
实发的键名**（脚本只验格式，验不了口径真假——两边用同一套假键名会自洽通过）、`action_spec` 之外的
动作语义（`format` 与 `dims` 已由 `action_spec` 用例机械比对；**值的真实含义**——`delta` 是不是真增量、
夹爪正负号、欧拉/轴角约定——仍要人工对上游）、
`EPISODE_START` 是否真清空了 KV cache 一类内部状态、`observation_params` 声明、权重标识进 provenance、
镜像不含凭据、`chmod -R a+rX`。下文条目保留全量——脚本是加速器，不是替代品。

## 平台怎么起它

```text
cmd  = shlex.split(customImage.command)，每个 token 把 {address}→0.0.0.0:<port>、{port}→<port> 字面替换
       Popen(list) 非 shell：命令里写 $MS_PORT 不会被展开
env  = 容器 env − 代理变量 + CUDA_VISIBLE_DEVICES(1 卡) + MS_PORT=<port> + 用户 envs
       不注入 HF_HOME / HF_HUB_OFFLINE / HF_MODULES_CACHE，要就自己经 envs 给
port = coordinator 从 8000 起跨 benchmark 全局递增分配
```

- 端口只能从 `{port}` / `{address}` 占位符或 `MS_PORT` env 取。控制面会拒绝写死端口的命令
  （`--port 8000`、`IP:端口`、`--address host:8000` 三种写法）。
- 用户 envs 黑名单（命中直接 400）：`EVAL_*` 等控制面注入项、`CUDA_VISIBLE_DEVICES`、`RAY_*` 前缀、`PYTHONPATH`、`MS_PORT`、代理变量。
- ckptPath 必填。

## 自建推理服务鉴权（Bearer）

同一个 MS 除了打成自定义镜像由平台拉起，也可以自己部署、以「自建推理服务」（`modelTypeName=selfHosted`）接入。
只有自建这条路径会带 Token；**平台拉起的自定义镜像，平台探 `/config` 不带鉴权头**，MS 若强制鉴权会探活 900s 超时。
所以鉴权要做成**可开关**：从环境变量读 Token，读不到就不鉴权（见 `脚本模板.md`「Bearer 鉴权」）。

平台对自建地址的行为（数据面探活与 BA 连接同口径）：

```text
探活（每个 BA 节点 × 每个地址，attachTimeoutSec 内每 5s 重试，默认 300s；不走代理）
  1. GET /health                   带 Authorization: Bearer <token>
  2. 非 200 → GET /config          同上；两者有一个 200 才继续
  3. GET <地址的 path+query>        WebSocket Upgrade，同上；只认 101，不发 HELLO
状态码 → 结论
  401 / 403        inference_auth_rejected   立即放弃，不再重试
  5xx              inference_not_ready       继续重试到 attach 超时
  其他非 101       inference_ws_rejected
评测期间
  BA 的 harness 从 VLA_EVAL_SERVER_TOKEN 读 Token，每次握手（含断线重连）都带 Bearer
  单帧推理超时 serverTimeoutSec（默认 60s）
```

- [ ] `/health`、`/config` 是**根路径**，与地址里的 path 无关；前面挂反向代理时这两个路径也要放行到 MS
- [ ] 鉴权在 `process_request` 里、**握手之前**完成：不通过直接回 401，不要先 101 再在 HELLO 里拒
- [ ] 不通过只回 **401/403**，不要回 500：5xx 会被当成「还在加载」重试到 attach 超时，报错指不到 Token
- [ ] `/health`、`/config`、WS 握手**同一套校验**：只拦握手不拦 HTTP 也能过探活，但别人能匿名改 `/config`
- [ ] 比较用 `hmac.compare_digest`，Token 只从环境变量读，**不进命令行、不进日志、不进 HELLO 应答**
- [ ] Token 满足控制面规则：不带 `Bearer ` 前缀、16–4096 字节、字符集 `A-Z a-z 0-9 - . _ ~ + /`（末尾可接 `=`）；
      带 Token 时地址 query 不能再有 `token`/`access_token`/`auth`/`key`，地址不能带 userinfo/fragment
- [ ] 所选评测集都声明了支持鉴权头；BA 侧 harness 客户端需支持 `VLA_EVAL_SERVER_TOKEN`（平台基础镜像 ≥0.3.3）
- [ ] 地址是 BA 能直连的 IP 或公共顶级域名：控制面拒绝 localhost / 回环 / link-local / `.local` / `.svc` / 单段名

自检命令见下文「联调顺序」，加 Token 环境变量和 `--require-auth`。

## 启动与探活

- [ ] 监听 `0.0.0.0:<port>`，不能只听 `127.0.0.1`（BA 在另一个 Pod 连 `ws://<pod_ip>:<port>`）
- [ ] HTTP 与 WebSocket **同端口**
- [ ] 实现 `GET /config` 返 200（平台探 `/config` 不探 `/health`，每 2s 一次，900s 超时）
- [ ] HTTP 探活与 WS 握手**按请求头而非路径分流**：带 `Upgrade: websocket` 的请求一律放行给握手。
      BA 连的是无路径的 `ws://<pod_ip>:<port>`，其 `request.path` 为 `/`；若 `process_request` 只按
      路径判断（把 `/` 也当 `/config`），WS 握手会被 HTTP 200 顶掉，客户端报
      `server rejected WebSocket connection: HTTP 200`，而 `curl /config` 一切正常——真机踩过
- [ ] 权重加载 + warmup 在**开始监听之前**完成；`/config` 200 后平台立即发首帧
- [ ] 首帧 OBSERVATION→ACTION < 30s（默认单帧预算，HELLO 往返同口径）
- [ ] 子进程启动失败会立刻报 `ModelServer exited prematurely (rc=…)`，stdout/stderr 是唯一排障来源，不要静默吞日志

## 传输与信封

- [ ] WebSocket `ws://`，msgpack `use_bin_type=True`，二进制帧
- [ ] `compression=None`、`max_size=None`、**服务端显式 `ping_interval=None`**（长推理会被库默认心跳误杀）
- [ ] 信封四字段 `type` / `payload` / `seq` / `timestamp` 齐全（缺一即协议错误）
- [ ] 应答回显请求的 `seq`（`ACTION` 回显对应 `OBSERVATION`，`HELLO`、`ERROR` 同理）；服务端不自分配 seq

## 编解码

- [ ] 递归解任意嵌套层级的 `__ndarray__`：`dtype` 是 `dtype.str`（`<f4`、`|u1`，带字节序），kind 限 `b i u f`，
      `len(data) == prod(shape) * itemsize`
- [ ] `__image__` 的 `raw` / `jpeg` / `png` **三种都能解**（默认 png；格式由客户端配置决定，不能假设）
- [ ] 发出的动作用 `__ndarray__` 编码，不要发 list / 文本

## 观测对齐（逐项人工核，`obs_spec` 用例只验格式不验真假）

模型内部的相机命名与 benchmark 实发的观测键名是**两套命名空间**，完整论证见 `SKILL.md`「阶段 3.5」。

- [ ] 相机键名的出处写得出来：harness 同 benchmark 的参考 MS（`src/vla_eval/model_servers/<name>.py`）、
      benchmark 实现本身、或 `docs/reproductions/<name>.md`——**不是**开发机上手工跑通时用的那套
- [ ] `obs.<benchmark>.json` 里的键名**逐字**等于上面查到的键名（大小写、空格、下划线都算）
- [ ] MS 内部有「观测键名 → 模型槽位」的别名表，缺相机时 `raise` 并打出「要什么/实到什么/试过哪些别名」
- [ ] **没有**为了消除报错而改模型侧参数（image_prompts / 相机名等训练口径）——那会静默改变模型输入
- [ ] `HELLO` 的 `observation_spec.images` 里声明了每个槽位的 `accepted_keys`
- [ ] state 优先按 `<benchmark>.yaml` 写死的 `state_key` 取；三种兼容 `obs.get("state", obs.get("states", obs.get("joint_state")))`
      只作后备；维度与打包顺序对齐上游，**缺则抛错不补零**
      （线缆字段名按 benchmark 三分，RoboTwin 发的是 `joint_state`，对照 `评测集观测口径.md` §4）
- [ ] 图像的 RGB/BGR、HWC/CHW、dtype 与取值域、是否翻转都按上游口径核过
- [ ] `task_description` 的字段名对齐，取不到时不要静默用空串当 prompt

## 消息语义

- [ ] `HELLO` 应答含 `protocol_version: 1`、`harness_version`、`model_server`，并声明 `action_spec` / `observation_spec`
      （format 用预定义常量，少用 `raw`——它会关掉维度校验）
- [ ] 两份 spec 的字段名是 v0.9.0 的 `DimSpec` 口径 **`name` / `dims` / `format`**：
      `{"actions": {"name": "actions", "dims": 14, "format": "absolute_joint_positions_with_grippers"}}`。
      写成 `shape` / `dtype` 不会报错，只会让 `DimSpec.from_dict` 抛 `KeyError('name')`，被
      `orchestrator.py` 的 `except Exception: logger.warning("Spec validation failed: %s")` 吞成一条 warning
      ——**跨端 spec 校验等于没做**，维度错了要到出分数才发现
- [ ] 需要 state / 腕部相机时在 `observation_params` 里声明（如 `{"send_state": true}`），这是唯一能反向影响 BA 的通道；
      键名须在目标 benchmark `__init__` 或其 MRO 基类签名里（v0.9.0 不认的键丢弃并打 warning，`orchestrator.py:131`），
      且**提交评测时填的同名 key 优先级更高会静默压过本声明**，默认值已经对的也显式声明一次。
      机制与各 benchmark 默认值见 `评测集观测口径.md` §5
- [ ] 把权重标识写进 `HELLO` 应答（进结果 provenance，复现时唯一证据）
- [ ] `ACTION.actions` 是 **1-D 单步** `(action_dim,)`；chunk 在服务端缓存逐帧 pop，不上线缆
- [ ] sync 模式一问一答，一个 OBSERVATION 只回一个 ACTION
- [ ] `EPISODE_START` 重建 session 上下文并清空全部 per-episode 状态（chunk 缓冲、历史帧、KV cache、时钟）
- [ ] 形态 B：`HELLO` 应答**一般不声明** `capabilities`。v0.9.0 客户端只在服务端声明了 `episode_ready`
      时才等 `EPISODE_READY`（`connection.py:176`）；一旦声明 `episode_ready: true`，每个 `EPISODE_START`
      都必须回一条 `EPISODE_READY`（seq 回显），否则客户端等到超时
- [ ] **唯一例外：robodojo / ocbench 是 `VectorStepBenchmark`，必须声明 `capabilities: {"vector_step": true}`
      并实现 `VECTOR_STEP` → `VECTOR_RESULT`**（报文与语义见 `脚本模板.md`「形态 B 必做：VECTOR_STEP」）。
      缺这条不是「少个可选花样」：v0.9.0 `orchestrator.py:550-558` 的 `_run_vector` 开头就
      `raise RuntimeError("... does not take vector steps ...")`，benchmark 的 `hard_exit` 把它吞掉后
      `os._exit(1)`，线上形态是**提交日志只有 exit code 1 + 0 episode、没有任何 traceback，MS 日志只有
      connect→close、没有 `episode_start`**。v0.9.0 里只有这两个 benchmark 走 vector 路径
      （`git grep "VectorStepBenchmark)" v0.9.0 -- src/vla_eval/benchmarks/`，新增 benchmark 前要重查）
- [ ] `VECTOR_STEP` 的 `observations` 是**列式 batch**（`images.cam = [rows, H, W, 3]`），单槽位也是行数为 1；
      `actions` 只回未失败的 slot，行序等于 `slots` 顺序；只带 `ends` 的收尾轮也要回一条 `vector_result`
- [ ] 带 `recording.sid` 时用它覆盖 session_id
- [ ] per-episode 状态按 `session_id` 分桶（形态 B）/ 按 `row.id` 分桶（形态 A，基类已分好），不用进程级单变量（多 shard 共享一个 MS）
- [ ] 推理异常回 `ERROR{"error": "observation_failed: <Exc>: <msg>"}`，**不关连接、不返零动作**
- [ ] 断线重连只重发 `HELLO`；收到无 episode 上下文的 `OBSERVATION` 不崩（惰性建或回 ERROR）
- [ ] 连接断开时若仍在 episode 中，兜底做一次清理
- [ ] `EPISODE_END` 只记录，不改写成功判据

## 联调顺序

本地 HELLO 往返 → 单 episode 单帧 → 完整 episode → 多 episode 串行（验状态重置）
→ 双连接并发（验 session 分桶）→ 以 `开发机改造.md`「自检」口径（`env -i` + 死代理）复跑。
到这里就是本 skill 的交付门禁；再往后的平台级冒烟由用户交付后自行在控制台提交。

前五步不要手敲客户端，`scripts/ms_selfcheck.py` 一条命令全跑（主路径）：

```bash
MS_PORT=8000 <你的启动命令> &
"$MODEL_ENV/bin/python" ms_selfcheck.py \
  --url ws://127.0.0.1:8000 --obs-spec obs.<benchmark>.json   # 要「n/n 通过」+ 退出码 0；每个 benchmark 各一遍
```

benchmark 有构造参数时（robotwin `action_type`、calvin `absolute_action`），**再按提交评测实际用的值跑一遍**：

```bash
"$MODEL_ENV/bin/python" ms_selfcheck.py --url ws://127.0.0.1:8000 \
  --obs-spec obs.robotwin.json --benchmark robotwin --bench-param action_type=ee
```

robotwin 声明 `ee_pose` 16D 而不带这条时，用例只打提示就 PASS；BA 侧若仍走默认 `qpos`，
16D 会被静默截断成 14、整场分数作废。参数名拼错（`action_typ=ee`）直接 FAIL，不会静默失效。

MS 开了 Bearer 鉴权（自建推理服务场景）时再跑一遍带 Token 的：MS 与自检读同一个环境变量，
`auth` 用例会补上不带 Token、错 Token 两条反向用例。Token 只经环境变量传，自检输出里一律打成 `Bearer ***`：

```bash
export VLA_EVAL_SERVER_TOKEN=<token>          # MS 侧读同名变量（或 --token-env 指定别的变量名）
MS_PORT=8000 <你的启动命令> &
"$MODEL_ENV/bin/python" ms_selfcheck.py --url ws://127.0.0.1:8000 \
  --obs-spec obs.<benchmark>.json --benchmark <benchmark> --require-auth   # --require-auth：忘了 export 时判 FAIL，而不是静默跳过鉴权用例
```

无 Token 那一遍也要过：它对应平台拉起自定义镜像的路径，证明「没配 Token 就不鉴权」的开关是好的。

解释器用 `setup.sh` 判出的模型环境，**不要用裸 `python3`**——重档机上它常是系统解释器，
没装 `websockets`/`msgpack`，会以 ImportError 挂掉，看起来像脚本坏了、实际是解释器选错。

模型环境里装了 harness 时可另跑一次做交叉验证，但**不替代**上面这步（它才与平台数据面同口径）：

```bash
vla-eval test -c <server-config>.yaml      # 发 dummy 观测，校验 HELLO / 动作维度
```

## 常见误区速查

| 误区 | 实际 |
|---|---|
| 平台探 `/health` | 探 `/config` |
| 端口固定 8000 | 从 8000 起全局递增。**优先在进程里读 `MS_PORT`**，命令里就不必出现端口；`{port}`/`{address}` 占位符也合法 |
| 命令里写 `$MS_PORT` 就行 | 非 shell 启动不展开，必须在进程里读 env（或用占位符）。**不要靠 `bash -lc` 展开**——`-l` 读 login profile，会把 PATH / `$HOME` 带进来，违反「不依赖 PATH 与 `$HOME`」这条底线 |
| raw 路径也有 HF_* 默认值 | 不注入，自己给 |
| ACTION 可以回 2-D chunk | 线缆上必须 1-D 单步 |
| ERROR 后连接会断 | 刻意不断 |
| 改参数走 `POST /config` | `GET /config?key=value`，白名单只有 `max_batch_size` / `max_wait_time` |
| Ray 差个小版本没事 | 连不上 GCS，Pod 卡 Init，不报版本错 |
| 推理栈必须迁到 Python 3.13 | 只有组集群解释器受约束 |
| 鉴权失败回 500 / 关连接就行 | 必须握手前回 401/403：5xx 会被平台当未就绪重试到 attach 超时 |
| 只拦 WS 握手，`/health` 放开 | 平台探活带 Token 探 `/health`、`/config`，同一套校验；放开 `/config` 等于允许匿名改参数 |
| 镜像里也强制鉴权 | 平台拉起自定义镜像时探 `/config` 不带 Token；没配 Token 必须不鉴权 |
| Token 用 `--token xxx` 传 | 命令行会进 `ps`、进日志；MS 与自检都只从环境变量读 |
