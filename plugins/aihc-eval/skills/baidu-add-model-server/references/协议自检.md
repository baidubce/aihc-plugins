# 协议自检（用户自定义镜像）

本文是 policy protocol（`protocol_version = 1`）的逐条可验版，外加平台 raw 启动路径的实际行为。
用 harness `PredictModelServer` 实现的服务天然满足协议段（`脚本模板.md` 形态 A），
只需过「平台侧」与「启动」两段；自己实现协议（形态 B）则要整篇逐条打勾。

## 哪些条目已被脚本自动判定

打勾不靠肉眼：下表的条目由 `scripts/ms_selfcheck.py` 对着**跑起来的 MS** 自动验（用例名就是失败时打出来的 tag），
平台侧的 Ray 条目由 `scripts/ray_env_check.sh` 验。**先跑脚本，再人工过剩下的。**

| 脚本用例 | 覆盖的条目 |
|---|---|
| `obs_spec` | **口径门禁**：`--obs-spec` 必须给（缺省即 FAIL）；每路 shape 是 `[H, W, C]` 正整数且 `C∈{1,3,4}`；`states` 是显式整数；`task_description` 非空 |
| `config` | `GET /config` 200；`GET /config?max_batch_size=1` 仍 200 |
| `hello` | 信封四字段、`seq` 回显、`protocol_version: 1`、`model_server` 非空；声明的相机键名与将发送的键名零交集时打 INFO |
| `inference` | 首帧 < 30s（可调）、一问一答、`ACTION` 是 `__ndarray__` 编码的 1-D 有限值且与 `action_spec` 维度一致、两个 episode 串行不报错 |
| `image_formats` | `__image__` 的 `raw` / `jpeg` / `png` 与裸 `__ndarray__` 四种都能解 |
| `error_resilience` | 畸形观测回 `ERROR`（或可解释的 ACTION）、**不关连接**、下一帧能恢复 |
| `no_episode_context` | 无 episode 上下文的 `OBSERVATION` 不崩（惰性建或回 ERROR） |
| `session_isolation` | 双连接并发、各带不同 `recording.sid` 都能拿到合法 ACTION |
| `ray_env_check.sh` | 下文「平台侧」前 4 条 |

脚本**验不到**的（必须人工）：ckpt 路径与日志核对、**`obs.<benchmark>.json` 里的相机键名是否真等于目标 benchmark
实发的键名**（脚本只验格式，验不了口径真假——两边用同一套假键名会自洽通过）、动作语义与上游对齐、
`EPISODE_START` 是否真清空了 KV cache 一类内部状态、`observation_params` 声明、权重标识进 provenance、
镜像不含凭据、`chmod -R a+rX`。下文条目保留全量——脚本是加速器，不是替代品。

## 平台怎么起它

```text
cmd  = shlex.split(customImage.command)，每个 token 把 {address}→0.0.0.0:<port>、{port}→<port> 字面替换
       Popen(list) 非 shell：命令里写 $MS_PORT 不会被展开
env  = 容器 env − 代理变量 + CUDA_VISIBLE_DEVICES(1 卡) + MS_PORT=<port> + 用户 envs
       不注入 HF_HOME / HF_HUB_OFFLINE / HF_MODULES_CACHE，要就自己经 envs 给
port = coordinator 从 8000 起跨 benchmark 全局递增分配
```

- 端口只能从 `{port}` / `{address}` 占位符或 `MS_PORT` env 取。控制面会拒绝写死端口的命令
  （`--port 8000`、`IP:端口`、`--address host:8000` 三种写法）。
- 用户 envs 黑名单（命中直接 400）：`EVAL_*` 等控制面注入项、`CUDA_VISIBLE_DEVICES`、`RAY_*` 前缀、`PYTHONPATH`、`MS_PORT`、代理变量。
- ckptPath 必填。

## 启动与探活

- [ ] 监听 `0.0.0.0:<port>`，不能只听 `127.0.0.1`（BA 在另一个 Pod 连 `ws://<pod_ip>:<port>`）
- [ ] HTTP 与 WebSocket **同端口**
- [ ] 实现 `GET /config` 返 200（平台探 `/config` 不探 `/health`，每 2s 一次，900s 超时）
- [ ] HTTP 探活与 WS 握手**按请求头而非路径分流**：带 `Upgrade: websocket` 的请求一律放行给握手。
      BA 连的是无路径的 `ws://<pod_ip>:<port>`，其 `request.path` 为 `/`；若 `process_request` 只按
      路径判断（把 `/` 也当 `/config`），WS 握手会被 HTTP 200 顶掉，客户端报
      `server rejected WebSocket connection: HTTP 200`，而 `curl /config` 一切正常——真机踩过
- [ ] 权重加载 + warmup 在**开始监听之前**完成；`/config` 200 后平台立即发首帧
- [ ] 首帧 OBSERVATION→ACTION < 30s（默认单帧预算，HELLO 往返同口径）
- [ ] 子进程启动失败会立刻报 `ModelServer exited prematurely (rc=…)`，stdout/stderr 是唯一排障来源，不要静默吞日志

## 传输与信封

- [ ] WebSocket `ws://`，msgpack `use_bin_type=True`，二进制帧
- [ ] `compression=None`、`max_size=None`、**服务端显式 `ping_interval=None`**（长推理会被库默认心跳误杀）
- [ ] 信封四字段 `type` / `payload` / `seq` / `timestamp` 齐全（缺一即协议错误）
- [ ] 应答回显请求的 `seq`（`ACTION` 回显对应 `OBSERVATION`，`HELLO`、`ERROR` 同理）；服务端不自分配 seq

## 编解码

- [ ] 递归解任意嵌套层级的 `__ndarray__`：`dtype` 是 `dtype.str`（`<f4`、`|u1`，带字节序），kind 限 `b i u f`，
      `len(data) == prod(shape) * itemsize`
- [ ] `__image__` 的 `raw` / `jpeg` / `png` **三种都能解**（默认 png；格式由客户端配置决定，不能假设）
- [ ] 发出的动作用 `__ndarray__` 编码，不要发 list / 文本

## 观测对齐（逐项人工核，`obs_spec` 用例只验格式不验真假）

模型内部的相机命名与 benchmark 实发的观测键名是**两套命名空间**，完整论证见 `SKILL.md`「阶段 3.5」。

- [ ] 相机键名的出处写得出来：harness 同 benchmark 的参考 MS（`src/vla_eval/model_servers/<name>.py`）、
      benchmark 实现本身、或 `docs/reproductions/<name>.md`——**不是**开发机上手工跑通时用的那套
- [ ] `obs.<benchmark>.json` 里的键名**逐字**等于上面查到的键名（大小写、空格、下划线都算）
- [ ] MS 内部有「观测键名 → 模型槽位」的别名表，缺相机时 `raise` 并打出「要什么/实到什么/试过哪些别名」
- [ ] **没有**为了消除报错而改模型侧参数（image_prompts / 相机名等训练口径）——那会静默改变模型输入
- [ ] `HELLO` 的 `observation_spec.images` 里声明了每个槽位的 `accepted_keys`
- [ ] state 优先按 `<benchmark>.yaml` 写死的 `state_key` 取；三种兼容 `obs.get("state", obs.get("states", obs.get("joint_state")))`
      只作后备；维度与打包顺序对齐上游，**缺则抛错不补零**
      （线缆字段名按 benchmark 三分，RoboTwin 发的是 `joint_state`，对照 `评测集观测口径.md` §4）
- [ ] 图像的 RGB/BGR、HWC/CHW、dtype 与取值域、是否翻转都按上游口径核过
- [ ] `task_description` 的字段名对齐，取不到时不要静默用空串当 prompt

## 消息语义

- [ ] `HELLO` 应答含 `protocol_version: 1`、`harness_version`、`model_server`，并声明 `action_spec` / `observation_spec`
      （format 用预定义常量，少用 `raw`——它会关掉维度校验）
- [ ] 需要 state / 腕部相机时在 `observation_params` 里声明（如 `{"send_state": true}`），这是唯一能反向影响 BA 的通道；
      键名须在目标 benchmark `__init__` **自身**签名里（v0.5.0 不走 MRO，不认的键**静默丢弃**无 warning），
      且**提交评测时填的同名 key 优先级更高会静默压过本声明**，默认值已经对的也显式声明一次。
      机制与各 benchmark 默认值见 `评测集观测口径.md` §5
- [ ] 把权重标识写进 `HELLO` 应答（进结果 provenance，复现时唯一证据）
- [ ] `ACTION.actions` 是 **1-D 单步** `(action_dim,)`；chunk 在服务端缓存逐帧 pop，不上线缆
- [ ] sync 模式一问一答，一个 OBSERVATION 只回一个 ACTION
- [ ] `EPISODE_START` 重建 session 上下文并清空全部 per-episode 状态（chunk 缓冲、历史帧、KV cache、时钟）
- [ ] 带 `recording.sid` 时用它覆盖 session_id
- [ ] per-episode 状态按 `session_id` 分桶，不用进程级单变量（多 shard 共享一个 MS）
- [ ] 推理异常回 `ERROR{"error": "observation_failed: <Exc>: <msg>"}`，**不关连接、不返零动作**
- [ ] 断线重连只重发 `HELLO`；收到无 episode 上下文的 `OBSERVATION` 不崩（惰性建或回 ERROR）
- [ ] 连接断开时若仍在 episode 中，兜底做一次清理
- [ ] `EPISODE_END` 只记录，不改写成功判据

## 平台侧（镜像）

全文见 `Ray环境.md`，这里只留可勾项：

- [ ] 组集群解释器：`ray[default]==2.49.2` 精确等值 + Python `3.13.12` patch 级一致
- [ ] 裸 `ray` 在**镜像 ENV 的 PATH** 上且是第一个（KubeRay 跑 `ray start` / `ray health-check`，只认第一个）
- [ ] Ray 那个 venv **只装** Ray；模型依赖留在独立环境，避免解析时改动 `ray` / `grpcio` / `protobuf`
- [ ] 以运行时同口径断言过——**直接跑 `scripts/ray_env_check.sh`**，它自己取 `/proc/1/environ` 的 PATH、
      核「第一个 ray」、以 `env -i` 跑 `ray --version` 与 `ray health-check --help`，并按 shebang 反查解释器验
      `ray.__version__` / python 版本。打出 `RAY_ENV_OK` 且退出码 0 才算过，**不要手敲一遍断言**
- [ ] 交付前清理之后再跑一次同一份脚本（与改造时同口径）：

```bash
bash /opt/ms-<name>/ray_env_check.sh
```

- [ ] 运行时无外网、无代理：tokenizer / remote code / 编译产物在改造期落盘并断言存在
- [ ] 用 HF 栈时自己在 envs 里给 `HF_HOME`、`HF_HUB_OFFLINE=1`，以及**可写**的 `HF_MODULES_CACHE`
- [ ] 镜像不含凭据、代理、`HF_TOKEN`
- [ ] 落盘内容都在 `/opt/*` 且 `chmod -R a+rX`（运行时用户未必是 root）

## 联调顺序

本地 HELLO 往返 → 单 episode 单帧 → 完整 episode → 多 episode 串行（验状态重置）
→ 双连接并发（验 session 分桶）→ 以 `开发机改造.md`「自检」口径（`env -i` + 死代理）复跑。
到这里就是本 skill 的交付门禁；再往后的平台级冒烟由用户交付后自行在控制台提交。

前五步不要手敲客户端，`scripts/ms_selfcheck.py` 一条命令全跑（主路径）：

```bash
MS_PORT=8000 <你的启动命令> &
"$MODEL_ENV/bin/python" ms_selfcheck.py \
  --url ws://127.0.0.1:8000 --obs-spec obs.<benchmark>.json   # 要「n/n 通过」+ 退出码 0；每个 benchmark 各一遍
```

解释器用 `setup.sh` 判出的模型环境，**不要用裸 `python3`**——重档机上它常是系统解释器，
没装 `websockets`/`msgpack`，会以 ImportError 挂掉，看起来像脚本坏了、实际是解释器选错。

模型环境里装了 harness 时可另跑一次做交叉验证，但**不替代**上面这步（它才与平台数据面同口径）：

```bash
vla-eval test -c <server-config>.yaml      # 发 dummy 观测，校验 HELLO / 动作维度
```

## 常见误区速查

| 误区 | 实际 |
|---|---|
| 平台探 `/health` | 探 `/config` |
| 端口固定 8000 | 从 8000 起全局递增。**优先在进程里读 `MS_PORT`**，命令里就不必出现端口；`{port}`/`{address}` 占位符也合法 |
| 命令里写 `$MS_PORT` 就行 | 非 shell 启动不展开，必须在进程里读 env（或用占位符）。**不要靠 `bash -lc` 展开**——`-l` 读 login profile，会把 PATH / `$HOME` 带进来，违反「不依赖 PATH 与 `$HOME`」这条底线 |
| raw 路径也有 HF_* 默认值 | 不注入，自己给 |
| ACTION 可以回 2-D chunk | 线缆上必须 1-D 单步 |
| ERROR 后连接会断 | 刻意不断 |
| 改参数走 `POST /config` | `GET /config?key=value`，白名单只有 `max_batch_size` / `max_wait_time` |
| Ray 差个小版本没事 | 连不上 GCS，Pod 卡 Init，不报版本错 |
| 推理栈必须迁到 Python 3.13 | 只有组集群解释器受约束 |
