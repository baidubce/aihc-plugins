# 恢复点

中断后（会话压缩、换会话、用户说「继续接 benchmark」）靠两个文件续上，不靠记忆。

## 1. 文件位置

| 文件 | 位置 | 为什么放这里 |
|---|---|---|
| `PROGRESS`、`form.yaml` | 开发机 `$W` | 设计文档：每步结束写 `$W/PROGRESS`；G1 授权后才写 |
| 冒烟产物、自检 JSON | 开发机 `$W` | 体积大，且要在开发机上跑 |

G1 授权前不写任何文件，`dry_run` 模式下写 `PROGRESS` 的命令也只输出、由用户执行。两个文件里不写私钥内容和 Token。

## 2. `PROGRESS`

只追加、不改写，一行一事，字段用制表符分隔。步 1 在登录验证通过后 `mkdir -p $W` 并写两行：`G1	remote_exec`
与 `1 … 登录验证通过`。其余步在该步结束时写。

```text
<步号>	<完成时间>	<一句话结论>
G1	remote_exec|dry_run
G2	已确认	<form.yaml 的 sha256 前 8 位>
G3	已批准	<计划里列出的写落点>
setup	done	<改动的文件清单>
G4	PASS	<selfcheck.json 路径>
G5	一致	<交付的 command>
cleanup	done	<删除清单>（只写在本地归档的副本里，开发机上的 $W 此时已删）
rollback→<步号>	<改了哪个决定>
stop	<步号>	<原因>
```

`G2`、`G3`、`G4` 的批准只对写下时的 `form.yaml` 有效。`form.yaml` 之后变了，哈希对不上就当没批准。

## 3. `form.yaml`

步 4 的表单。字段、取值规则、出处标签与样例见 `接入表单.md`。

## 4. 续上的步骤

1. 问用户 SSH 命令与 `name`，重过一次登录验证（`echo connected`），再读 `$W/PROGRESS` 最后一行和 `$W/form.yaml`。
   `$W` 不在就先看本地归档：归档的 `PROGRESS` 最后一行是 `cleanup done`，说明接入已完成并清理过，不要重走；
   没有归档才从步 1 开始。不重问 G1，除非最后一条 `G1` 是 `dry_run` 而用户现在要执行。
2. 用户说开发机没换过才续；换过按「开发机连不上」处理。
3. 按最后一行定位：

| 最后一行 | 接着做 |
|---|---|
| 步 1～3 的结论 | 重跑 `probe_form_defaults.sh`，与 `form.yaml` 里 `[探测]` 行对照，有差异先告诉用户 |
| `G2 已确认` / `G3 已批准` | 核对 `form.yaml` 哈希；一致就进下一步，不一致回步 4 |
| `setup done` | 远端 `ls /opt/bench`、`cat /opt/bench/start.sh` 对照计划，一致进步 7 |
| `G4 PASS` | 远端确认 `selfcheck.json` 还在且 `/opt/bench` 的 mtime 不晚于它，是就进步 8，否则重跑步 7 |
| `G5 一致` | 交付说明已出、尚未清理，接着做 SKILL.md 的「收尾清理」 |
| `rollback→N` | 从第 N 步重走，见 `改主意回退.md` |
| `stop` | 先问用户要不要接着做 |

4. 开发机连不上（Pod 已释放）：`$W` 连同 `PROGRESS`、`form.yaml` 一起没了，从步 1 重走。会话里还记得的
   `[用户]`、`[源码]` 行可请用户确认后沿用，`[探测]` 行在新机上重探。
