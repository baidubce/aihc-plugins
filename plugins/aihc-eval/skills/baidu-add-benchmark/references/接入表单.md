# 接入表单

步 4 预填、G2 确认的表单，存开发机 `$W/form.yaml`，与 `$W/PROGRESS` 同目录（见 `恢复点.md`）。
前五个字段对应控制台条目与镜像内容，其余是改造与冒烟要用的参数。

## 1. 字段

| 字段 | 去处 | 取值规则 |
|---|---|---|
| `name` | 控制台条目 `name`；`eval.yaml` 条目名用 `${oc.env:EVAL_BA_BENCH_NAME}` 引用它 | 用户给；须匹配 `^[a-z][a-z0-9_]{0,31}$`（平台校验规则），小写字母开头，不能有 `-`、`.` |
| `command` | 控制台条目 `command` | 固定 `bash /opt/bench/start.sh`，与冒烟 `--command` 逐字一致（G5） |
| `envs` | 控制台条目 `envs` | 不含 `EVAL_BA_*`（平台下发的同名键会覆盖用户值），不含代理变量与凭据 |
| `config_path` | 镜像内 `eval.yaml` 路径，`start.sh` 的 `--config` | 固定 `/opt/bench/eval.yaml`，单条目，模板见 `命令契约.md` 第 3 节 |
| `assets` | 资产方式与落点 | 只有两种：`none`（无外部资产）或 `image:<根盘路径>`（打进镜像，如 `/opt/bench/assets/<name>`）；附文件数与总字节，见 `渲染与资产.md` 第 5 节 |
| `grade` | 分级 | `probe_form_defaults.sh` 的 `grade_hint`，A? / C? 须经步 3 核对后改成定档 |
| `bench_env` | 评测 env | 探测结果，猜错时用 `BENCH_ENV=` 重探 |
| `benchmark` / `params` | `eval.yaml` 条目 | 删掉探测 `yaml_platform_keys` 列出的键；观测开关（如 LIBERO 的 `send_wrist_image` / `send_state`）不写，由模型服务经 HELLO 声明，写死会覆盖模型的选择 |
| `max_steps` | `eval.yaml` 条目 | 正整数，取原评测的 horizon；各 suite horizon 不同时，一个条目只对应一个 suite，见第 3 节 |
| `tasks` / `seed` / `success` | 交付说明 | 与 `max_steps` 合称 G2 四项，必须有出处 |
| `action_dim` | echo MS 的 `--action-dim` | 与目标模型一致 |

运行时不依赖外网：`assets` 只能是镜像内路径，不能是下载地址或挂载盘（保存镜像不带挂载盘）。

## 2. 格式

每行写值和出处，出处标签只用三种：`[用户]`、`[探测]`（`probe_form_defaults.sh` 的输出）、`[源码]`（附 `文件:行`）。

```yaml
name: libero_spatial            # [用户]
command: bash /opt/bench/start.sh   # 固定
envs: {}                        # [用户]，不含 EVAL_BA_*
config_path: /opt/bench/eval.yaml   # 固定
assets: none                    # [探测]；打进镜像时写 image:/opt/bench/assets/<name>，并记文件数、总字节
grade: A                        # [探测] grade_hint
bench_env: /opt/conda/envs/libero   # [探测]
benchmark: "vla_eval.benchmarks.libero.benchmark:LIBEROBenchmark"   # [探测] yaml_benchmark
params: {suite: libero_spatial, seed: 7}   # [探测]；seed 出处另记
max_steps: 220                  # [源码] vla_eval/benchmarks/libero/benchmark.py:49
tasks: 全部 10 个               # [源码] <文件:行>
success: env 的 done 信号       # [源码] <文件:行>
action_dim: 7                   # [用户]，echo MS 的 --action-dim 用它
```

`max_steps`、`tasks`、`seed`、`success` 四行是 G2 要求有出处的项，`[探测]` 不够，必须补到 `[源码]` 或 `[用户]`。

## 3. 多个 suite

`eval.yaml` 只有一个条目、一个 `max_steps`，平台按它算超时；`start.sh` 按 suite 改步数，平台不知道。horizon 还会改变
失败 episode 跑多久，进而改变成功率。所以：

- 各 suite 的 horizon 相同：一个条目，suite 由控制台 subBench 下发（`EVAL_BA_SUB_BENCH`）。
- horizon 不同（LIBERO 就是，spatial 220、libero_10 520）：一个镜像只接一个 suite，name 带 suite 名；`start.sh` 遇到
  其他 `EVAL_BA_SUB_BENCH` 非 0 退出。不要把 `max_steps` 写成各 suite 的最大值。
- 步 2 问原评测入口时一并问要接哪个 suite，写进 `form.yaml` 的 `[用户]` 行。
