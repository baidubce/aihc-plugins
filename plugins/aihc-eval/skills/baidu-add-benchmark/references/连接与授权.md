# 连接与授权

步 1 的做法。流程与 `baidu-add-model-server` 的同名文件一致，这里只写 BA 的差异和要点。

## 1. 收集

- 问开发机的公网访问地址 `<host>:<port>`。用户给了整条 SSH 命令就从中解析，不再问。
- 拼成 `ssh -p <port> [-i <key_path>] <user>@<host> -o StrictHostKeyChecking=accept-new`，用户名默认 `root`。
  不是 root 就停：`/opt/bench` 与 conda env 都按 root 写。
- 命令里带远端命令、管道、重定向的，先规范成只剩连接参数；规范不了就请用户重给。
- 只给 host 没给 port 时问端口，不默认 22。

## 2. 探端口 → G1 → 验登录

顺序固定，不得颠倒。

1. 本地 TCP 探测，不登录，可直接跑：`nc -z -w 5 <host> <port> && echo "tcp open" || echo "tcp unreachable"`。
   不通就报给用户，选项：先停 / 重探（至多 2 次）/ 重输地址 / 取消。
2. **G1**（未授权不执行写命令），用客户端的结构化提问工具（Claude Code 里是 `AskUserQuestion`；客户端没有这类工具时，
   改为在一条消息里按编号列出下面四个选项，用户回复编号即视为点选，判定规则不变），题干带 SSH 命令（私钥只显示路径）、`tcp open`，
   并列出授权后要跑的命令（`echo connected`、`mkdir -p $W` 并写 `PROGRESS`、`probe_form_defaults.sh`、
   `ray_env_check.sh`），方便用户一次放行：
   - 授权连接、写 `$W` 并执行探测（推荐）→ `CONN_MODE=remote_exec`
   - 只生成命令不执行 → `CONN_MODE=dry_run`，之后每条命令只输出、不执行，用户自己跑后贴回结果
   - 重输地址 → 回第 1 节
   - 取消 → 结束
3. 登录验证（仅 `remote_exec`）：`<SSH_CMD> -o BatchMode=yes "echo connected"`，输出 `connected` 且退出码 0 才算过。
   失败静默重试 1 次，仍失败按下表提示，选项：先停 / 重输 / 只生成命令 / 取消。

| 现象 | 提示 |
|---|---|
| `Permission denied` | 核对私钥路径、用户名、开发机是否已放公钥 |
| `Connection timed out` / `No route to host` | 核对开发机状态、端口、安全组 |
| `Host key verification failed` | Pod 多半重建过，给 `ssh-keygen -R "[<host>]:<port>"`，不当瞬断重试 |
| 私钥带口令导致 BatchMode 失败 | 提示 `! ssh-add <key>`；密码登录不支持，请改用密钥 |

## 3. G1 授权的范围

G1 授权连接、只读命令（`ls`、`find`、`cat`、`nvidia-smi`、`probe_form_defaults.sh`、`ray_env_check.sh`），
以及往 `$W` 写 `PROGRESS`、`form.yaml`、`ray_env_check.log`。未经 G1 不执行任何写命令。
改造类写操作（`/opt/bench`、装包、拷脚本）要等 **G3** 用户确认计划后才开始，且只写计划里列出的两处：

| 落点 | 内容 |
|---|---|
| `$W`（默认 `/root/workspace/ba-<name>`） | echo MS 端口与日志、冒烟产物、自检 JSON |
| `/opt/bench` | `eval.yaml`、`start.sh`，及适配器代码（如有） |

装包（`pip install` 进用户的 conda env）也属于写，同样列进 G3 计划。不动 `/opt/conda/bin` 下 base 的 Ray 解释器，
不动 `harness_root` 下的 harness 源码树。`/opt/bench` 已存在且非空（探测会报 `opt_bench`）时，先给用户看内容，
不覆盖。

步 8 的收尾清理（见 SKILL.md）也属于写，G3 计划里要一并列出：交付后删哪些路径，保留 `/opt/bench` 与评测 env。
不在这份清单里、又拿不准来源的路径，删之前先问用户。

## 4. 执行纪律

- 多行远端脚本一律 `<SSH_CMD> -o BatchMode=yes 'bash -s' < 脚本` 或 heredoc `'bash -s' <<'REMOTE' … REMOTE`，
  不对 `SSH_CMD` 用 `eval`。heredoc 开头先 `export PYTHONPATH="${PYTHONPATH:-}"`（conda 激活脚本会读它）。
- 要在评测 env 里跑的脚本（`echo_ms.py`、`smoke_run.py`、`ba_selfcheck.py`）先 `scp` 到 `$W/skill/`，这也是写，
  放在 G3 之后。脚本兼容 Python 3.8 及以上，评测 env（harness 0.9.0 要求 ≥ 3.11）与 base 都能跑。
- 不读、不打印、不上传私钥；不回显 Token、AK/SK。读 `/proc/1/environ` 时只 grep 需要的键。
- 交付说明与 skill 文件里不写开发机地址和端口。
