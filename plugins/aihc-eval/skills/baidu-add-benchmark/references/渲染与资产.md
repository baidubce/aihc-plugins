# 渲染与资产

> MuJoCo EGL 路径已由 B 档 MetaWorld MT1 样例验证，其他仿真器的 cpu 路径与资产落点仍未验证。B 档写适配器、或冒烟 `render_device`（M10）不过时读本文。
> 上游口径对齐 harness tag v0.9.0：`src/vla_eval/render.py`、`docs/render-backends.md`。

## 1. 平台怎么选渲染

| 环节 | 行为 |
|---|---|
| 控制面 | BA 资源 0 卡时须 `cpuRenderable=true`，否则创建被拒；0 卡下发 `EVAL_BA_RENDER=cpu`，有卡为 `gpu` |
| 数据面 | 每个 shard 注入 `MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl`、`EGL_PLATFORM=device`、`MUJOCO_EGL_DEVICE_ID`（`CUDA_VISIBLE_DEVICES` 首项），宿主有 NVIDIA ICD 时钉 `VK_ICD_FILENAMES`；代理变量一律剔除 |
| `start.sh` | 把 `--render "$EVAL_BA_RENDER"` 原样传给 `vla-eval run`（模板见 `命令契约.md`） |
| harness | 按适配器的 `render_backends` 校验，未声明的后端 fail fast；再调 `configure_render(mode)` 改本进程 env |

所以 gpu 路径上适配器通常什么都不用做（`configure_render` 返回 `{}`），cpu 路径靠适配器自己切。

## 2. 适配器侧

```python
render_backends = frozenset({"gpu", "cpu"})     # 只声明实测过的后端

@classmethod
def configure_render(cls, mode: str) -> dict[str, str]:
    from vla_eval import render
    return render.configure_mujoco_render(mode)  # cpu → MUJOCO_GL=osmesa 等三项
```

| 仿真器 | cpu 路径 | helper / 要点 |
|---|---|---|
| MuJoCo 系（LIBERO、RoboCasa、VLABench 等） | OSMesa | `configure_mujoco_render(mode)`；镜像要有 `libosmesa6` |
| SAPIEN 2.2 / 3.0.3（ManiSkill2、SimplerEnv、RoboMME） | lavapipe 软 Vulkan | `configure_sapien_render(mode, "<覆盖 ICD 的变量名>")`；要 Mesa ≥ 24.3；必须在第一次 `import sapien` 之前调用 |
| SAPIEN 3.0.0b1（RoboTwin、MIKASA） | 无 | 只声明 `gpu` |
| PyBullet（CALVIN） | TinyRenderer | 适配器自己切渲染器，帧与 gpu 路径接近但不逐像素一致 |
| JAX（Kinetix） | `JAX_PLATFORMS=cpu` | 无 GL |
| CoppeliaSim（RLBench） | Xvfb + Mesa GLX | 两条路径相同，cpu 不用改 env |
| Isaac Sim / Isaac Lab | 无 | 只声明 `gpu`，见 `上游缺口.md` C? 节 |

- 没测过 cpu 就不要声明 `cpu`。声明了却不生效，比不提供更糟：0 卡评测会静默落到别的设备或直接崩。
- 0 卡交付前用 `smoke_run.py --set EVAL_BA_RENDER=cpu` 单独冒烟一次（LIBERO 实测比 gpu 慢约 3.5 倍，`max_steps` 不变但超时余量要看）。

## 3. 不要做的事

| 做法 | 后果 |
|---|---|
| 镜像 ENV / Dockerfile `ENV` 写死 `VK_ICD_FILENAMES`、`MUJOCO_GL=osmesa`、`LIBGL_ALWAYS_SOFTWARE` | gpu 评测静默走软渲染，分数变、没人察觉。渲染变量只在构建期单条 `RUN` 里设 |
| `start.sh` 里 `export MUJOCO_GL=...` 覆盖平台注入值 | 同上；确需改由适配器的 `configure_render` 按 mode 改 |
| 在评测 env 里装 `mesa-vulkan-drivers` 后不检查 icd.d | loader 可能选中 lavapipe；探测脚本的 `vulkan_icds` 行应只有 `nvidia_icd.json`，有 `lvp*` 时确认平台会钉 NVIDIA ICD |
| 写死 `/etc/vulkan/icd.d/nvidia_icd.json` | 部分宿主只在 `/usr/share/vulkan/icd.d` 下有，写死必失败 |

Isaac 系多卡：平台下发 `EVAL_EXTRA_KIT_ARGS`（`--/renderer/activeGpu=<卡号> --/renderer/multiGpu/enabled=false
--/physics/cudaDevice=0`），`start.sh` 或适配器要原样拼进 Kit 启动参数，否则 N 个 shard 都铺到 0 号卡。

## 4. 验渲染设备

1. 冒烟前：在评测 env 里 `reset` 一个 task，存首帧 png 拿回本机看（`适配器指南.md` 第 5 节）。
2. 冒烟后：看 `$W/smoke/graphics_env.json`（子进程实际拿到的图形变量），自检 `render_device`（M10）查软渲染 ICD 与全黑帧。
3. gpu 路径在 shard 运行中 `nvidia-smi` 应能看到评测进程占显存；看不到多半落到了软渲染。
4. 最终由用户看一眼视频确认（底线 2）。

## 5. 资产

**平台运行时按无外网设计**。原评测会在首次运行时下载资产、clone 仓库、弹 license 确认的，全部挪到改造期做完。

| 项 | 做法 |
|---|---|
| 落点 | 资产放镜像根盘（overlay），如 `/opt/bench/assets/<name>`；不放 `$HOME`、`/tmp`、挂载盘（保存镜像不带挂载盘） |
| harness 缓存 | 上游适配器走 `vla_eval.dirs.assets_cache("<bench>")`，即 `$VLA_EVAL_ASSETS_CACHE > $VLA_EVAL_HOME/assets > ~/.cache/vla-eval/assets`；在 `start.sh` 或 envs 里把 `VLA_EVAL_ASSETS_CACHE` 指到根盘落点 |
| `ensure_git_clone` | 运行时目标目录已有 `.git` 才跳过；改造期先跑一次让它 clone 好 |
| license | `ensure_license` 在无 TTY 时直接 `SystemExit(1)`；用户确认接受后，在控制台 envs 里写 `VLA_EVAL_ACCEPTED_LICENSES=<id>`，交付说明写明 license id 与链接 |
| 只读 | 运行时用户未必是 root：`chmod -R a+rX` 资产目录；仿真器要写的缓存（编译 shader、解压纹理）另给可写目录 |
| 并发写 | N 个 shard 同时跑，可写缓存按 `EVAL_BA_SHARD_ID` 分目录或 `mktemp -d`，不共用一个锁文件 |
| HF | `HF_HOME` 指向只读位置时另给可写的 `HF_MODULES_CACHE`（自定义 benchmark 平台不替你补） |
| 校验 | 改造期记下资产的文件数与总字节（`find <dir> -type f | wc -l`、`du -sb <dir>`）写进交付说明，镜像保存后复核 |

验无外网：改造完在开发机上断开代理变量跑一次冒烟（`env -u http_proxy -u https_proxy ...`），确认没有下载动作。
开发机本身若无外网而原评测必须在线拉资产，停下告诉用户，不要自行配置代理写进镜像。

## 6. 资产太大

镜像层过大（几十 GiB）时保存与拉取都慢。这类情况先告诉用户体积，由用户决定是否继续；平台预置评测集的做法
（registry 侧追加资产层）不在本 skill 范围内。
