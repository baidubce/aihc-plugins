# 命令契约

平台对自定义 benchmark 的每个 shard 执行同一条 command：`Popen(shlex.split(command), start_new_session=True)`，
不经 shell。控制台 command 只填 `bash /opt/bench/start.sh`，一切逻辑写进 `start.sh`。

## 1. 子进程 env

叠加顺序（后者覆盖前者）：镜像 / Pod 环境 → 平台图形栈默认值 → 控制台 `envs` → 平台 `EVAL_BA_*`。
`envs` 里 `EVAL_BA_` 前缀的键与 `http_proxy` / `https_proxy` / `no_proxy` / `all_proxy` 会被平台丢弃。

| 变量 | 取值 | 说明 |
|---|---|---|
| `EVAL_BA_SERVER_URL` | `ws://<ip>:<port>` | 本 shard 绑定的模型服务 |
| `EVAL_BA_SHARD_ID` / `EVAL_BA_NUM_SHARDS` | `0..N-1` / `N` | 传给 `--shard-id` / `--num-shards` |
| `EVAL_BA_EVAL_ID` | 平台生成 | 传给 `--eval-id`，不得改写 |
| `EVAL_BA_OUTPUT_DIR` | 平台目录 | 传给 `--output-dir`，N 个 shard 共用，不得改写 |
| `EVAL_BA_RENDER` | `gpu` / `cpu` | 0 卡评测为 `cpu`，benchmark 须切软渲染 |
| `EVAL_BA_BENCH_NAME` | 控制台条目 name | 写进 `benchmark-field name` |
| `EVAL_BA_EPISODES_PER_TASK` | 平台缺省 10 | 冒烟用 1 |
| `EVAL_BA_MODE` | `sync` / `live` | 不得写死在 yaml |
| `EVAL_BA_RECORD_VIDEO` | `true` / `false` | 决定 `--record-video` / `--no-record-video` |
| `EVAL_BA_VIDEO_DIR` | `…/shard<i>` | 已按 shard 替换好，写进 `recording.output_dir` |
| `EVAL_BA_SUB_BENCH` | 可为空 | 非空时 `--param suite=…` |
| `EVAL_BA_SERVER_TIMEOUT` | 缺省 30 | `eval.yaml` 里 `server.timeout` 必须引用它 |
| `EVAL_BA_MODEL_NAME` / `EVAL_BA_MODEL_SOURCE` | 模型 framework / 来源 | 仅供参考，可不用 |
| `EVAL_BA_HARNESS_VERSION` | Head 上的 vla-eval 版本 | Head 没装时不下发，运行后核对跳过版本比对 |
| `VLA_EVAL_SERVER_TOKEN` | 自建推理地址的 Bearer Token | 仅自建地址开了鉴权时下发，见下文 |

`VLA_EVAL_SERVER_TOKEN` 由 harness 的 `ServerConfig.auth_token` 缺省读取，握手时带 `Authorization: Bearer`。
这个字段只有平台镜像里的 harness（位于 `/root/workspace/vla-evaluation-harness`）有，上游 v0.9.0 没有：装的是上游版本时，
Token 被忽略，握手静默 401、全部 episode 报错。`probe_form_defaults.sh` 的 `bench_env[...]` 行会打 `auth_token=有/无`，
是「无」就改装镜像里的 harness（`SETUPTOOLS_SCM_PRETEND_VERSION=0.9.0 pip install --no-deps -e <harness_root>`）。`start.sh` 不读、不打印、不经 argv 传它。

平台另设：`MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl`、`EGL_PLATFORM=device`、`MUJOCO_EGL_DEVICE_ID`（取
`CUDA_VISIBLE_DEVICES` 首项）、`VK_ICD_FILENAMES`（宿主有 NVIDIA ICD 时）、`EVAL_GPU_INDEX`，Isaac 系另有
`EVAL_EXTRA_KIT_ARGS`（`--/renderer/activeGpu=<物理卡号>` 等，`start.sh` 需原样拼到 Kit 启动参数里）。

## 2. `/opt/bench/start.sh` 模板

```bash
#!/usr/bin/env bash
# /opt/bench/start.sh —— 控制台 command 填：bash /opt/bench/start.sh
set -euo pipefail
source /opt/conda/etc/profile.d/conda.sh && conda activate mybench   # 用户自己的环境
if [[ "$EVAL_BA_RECORD_VIDEO" == "true" ]]; then rv=--record-video; else rv=--no-record-video; fi
sb=()   # 控制台条目填了 subBench 时才下发
if [[ -n "${EVAL_BA_SUB_BENCH:-}" ]]; then sb=(--param "suite=$EVAL_BA_SUB_BENCH"); fi
tk=()   # 可选：用户在 envs 填 EVAL_TASKS=a,b 时只跑这些 task
if [[ -n "${EVAL_TASKS:-}" ]]; then tk=(--benchmark-field "tasks=[$EVAL_TASKS]"); fi
exec vla-eval run --no-docker --yes \
  --config /opt/bench/eval.yaml \
  --server-url "$EVAL_BA_SERVER_URL" \
  --shard-id "$EVAL_BA_SHARD_ID" --num-shards "$EVAL_BA_NUM_SHARDS" \
  --eval-id "$EVAL_BA_EVAL_ID" --output-dir "$EVAL_BA_OUTPUT_DIR" --render "$EVAL_BA_RENDER" \
  --benchmark-field "name=$EVAL_BA_BENCH_NAME" --benchmark-field "subname=" \
  --benchmark-field "episodes_per_task=$EVAL_BA_EPISODES_PER_TASK" \
  --benchmark-field "mode=$EVAL_BA_MODE" \
  --benchmark-field "recording.record_step=false" \
  --benchmark-field "recording.output_dir=$EVAL_BA_VIDEO_DIR" \
  --benchmark-field "recording.filename_stem=task{task_idx:04d}_ep{episode_id:04d}" \
  --benchmark-field "recording.video_fps=20" \
  ${sb[@]+"${sb[@]}"} ${tk[@]+"${tk[@]}"} "$rv"
```

录屏块（`record_step=false`、`filename_stem`、`video_fps=20`）是平台口径，运行后核对会逐项比对，不要改。

依赖 CUDA 的仿真器（Isaac Sim、带 Warp / PhysX GPU 的）在 `source` 之后加一行：

```bash
export CUDA_VISIBLE_DEVICES="${CUDA_VISIBLE_DEVICES:-0}"
```

单卡评测平台不下发 `gpus_per_instance`，shard 的 actor 以 `num_gpus=0` 起，Ray 把 `CUDA_VISIBLE_DEVICES` 置成空串，
数据面对自定义 benchmark 也不补（`benchmark_actor.py` 的 `_build_env`），控制台 envs 又不让填这个键。
不加这行，Kit 报 `no CUDA-capable device is detected`，进程仍可能以 0 退出。多卡时平台已按 shard 钉好卡号，`:-` 不覆盖。
同时支持 cpu 渲染的仿真器要再判 `EVAL_BA_RENDER=gpu`，否则 0 卡 shard 会被当成有卡。
冒烟时用 `CUDA_VISIBLE_DEVICES= python scripts/smoke_run.py ...`（置空，不是不设）复现平台口径。

## 3. `/opt/bench/eval.yaml` 模板（只能有 1 个条目）

```yaml
server:
  timeout: ${oc.env:EVAL_BA_SERVER_TIMEOUT}   # 必须引用，不给默认值；url 由 --server-url 覆盖
benchmarks:
  - benchmark: "mybench.benchmark:MyBenchmark"
    max_steps: 400            # 必须显式写正整数，平台据此算超时数
    params: {suite: hard, seed: 7}
    hz: 10                    # 仅实时模式生效
```

## 4. CLI 覆盖行为（v0.9.0 `cli/main.py:58-94`、`config.py:277-290`）

- `--benchmark-field KEY=VALUE` 可重复、值按 YAML 解析、点号嵌套；除 `params` 外同一顶层键整体替换，
  多条 `recording.*` 合成一个新 dict 整块替换 yaml 里的 `recording`。
- `--record-video` / `--no-record-video` 对每个条目都生效，所以 yaml 只能有一个条目。
- `--param suite=…` 合并进 `params`。
- 必须带 `--no-docker`，防止 yaml 残留 `docker` 段。
- `tasks` 过滤后 `task_idx` 是过滤后的序号，视频文件名与明细都按它关联。
- 未知 task / suite 必须非 0 退出，不得回落默认值（否则 0 episode，被判 `bench_no_episodes`）。

## 5. 单 shard 隔离

N 个 shard 在同一 Pod 并发执行同一条 command：

| 要求 | 违反时的现象 |
|---|---|
| 不循环 shard、不并发起多个 `vla-eval run` | episode 重复，M8 `shared_queue` 报 `duplicated` |
| 最后一行 `exec`，不 `setsid`、不留后台进程 | 平台按进程组回收，脱组进程成孤儿 |
| 不监听固定端口（绑 0） | 第二个 shard 起不来，`smoke_run` 报非 0 退出 |
| 临时文件、缓存、锁按 `EVAL_BA_SHARD_ID` 分目录或 `mktemp` | 偶发损坏、视频解码失败 |
| 不改写 `EVAL_BA_OUTPUT_DIR` / `EVAL_BA_EVAL_ID` | 平台找不到 recording DB，M4 / M5 失败 |
